# คู่มือเริ่มต้นใช้งาน

คู่มือนี้อธิบายการติดตั้ง การเริ่มและหยุดระบบ การล้างข้อมูล และการแก้ปัญหาเบื้องต้นของ DojoMart บนเครื่องของผู้ทดสอบ

## 1. สิ่งที่ต้องมี

| รายการ | รายละเอียด |
|---|---|
| Git | สำหรับดาวน์โหลด (clone) ซอร์สโค้ด |
| Docker | Docker Desktop (Windows, macOS) หรือ Docker Engine พร้อม Docker Compose v2 (Linux) ตรวจสอบด้วย `docker --version` และ `docker compose version` |
| ทรัพยากรเครื่อง | หน่วยความจำว่างไม่น้อยกว่า 2 GB สำหรับ Docker และพื้นที่ดิสก์ประมาณ 1 GB |
| พอร์ตที่ว่าง | `8000` (หน้าเว็บ), `8001` (API) และ `8081` (ตัวดูฐานข้อมูล ไม่บังคับ) |
| เบราว์เซอร์ | Chrome, Firefox, Edge หรือ Safari รุ่นปัจจุบัน |
| เครื่องมือเรียก API | Postman หรือ curl (ดู `tools-and-tips.md`) |

## 2. การติดตั้งและเริ่มระบบครั้งแรก

1. ดาวน์โหลดซอร์สโค้ดและเข้าไปในโฟลเดอร์
   ```bash
   git clone <URL ของ repository ที่ผู้สอนกำหนด>
   cd test-dojo
   ```
2. เลือกเวอร์ชันที่ผู้สอนกำหนด (ทุกคนต้องทดสอบบนเวอร์ชันเดียวกัน)
   ```bash
   git checkout <แท็กเวอร์ชันที่ผู้สอนกำหนด>
   ```
3. (ไม่บังคับ) คัดลอกไฟล์ตั้งค่า หากต้องการเปลี่ยนพอร์ต
   ```bash
   cp .env.example .env
   ```
   บน Windows (PowerShell) ใช้ `Copy-Item .env.example .env`
4. สร้างและเริ่มระบบ
   ```bash
   docker compose up --build
   ```
   การรันครั้งแรกใช้เวลาสร้างภาพ (image) ประมาณ 1 ถึง 3 นาที และคำสั่งจะค้างอยู่เพื่อแสดงสถานะ หากต้องการให้ทำงานเบื้องหลังให้เติม `-d`
   ```bash
   docker compose up --build -d
   ```
5. เมื่อพร้อม ให้เปิดเบราว์เซอร์ที่ `http://localhost:8000` จะพบหน้า Sign in ใช้บัญชีทดสอบจาก `test-accounts-and-seed-data.md`

ตรวจสอบว่า API พร้อมใช้งานได้ที่ `http://localhost:8001/api/health` ซึ่งต้องตอบ `{"status":"ok"}`

## 3. พอร์ตและที่อยู่สำคัญ

| บริการ | ที่อยู่ | หมายเหตุ |
|---|---|---|
| หน้าเว็บ | `http://localhost:8000` | |
| API | `http://localhost:8001` | เส้นทางทั้งหมดขึ้นต้นด้วย `/api` ใช้ยิงตรงจาก Postman หรือ curl ได้ |
| ตัวดูฐานข้อมูล | `http://localhost:8081` | เปิดเฉพาะเมื่อใช้ profile `dbview` (หัวข้อ 6) |

## 4. คำสั่งที่ใช้บ่อย

| ต้องการ | คำสั่ง |
|---|---|
| เริ่มระบบ (เบื้องหลัง) | `docker compose up -d` |
| เริ่มระบบพร้อมสร้างภาพใหม่ | `docker compose up --build -d` |
| ดูสถานะคอนเทนเนอร์ | `docker compose ps` |
| หยุดระบบ (ข้อมูลยังอยู่) | `docker compose down` |
| ดูข้อความจากคอนเทนเนอร์ (เมื่อแก้ปัญหาการติดตั้ง) | `docker compose logs api` |

การหยุดด้วย `docker compose down` **ไม่ล้างข้อมูล** เมื่อเริ่มระบบใหม่จะได้ข้อมูลเดิม

## 5. การล้างข้อมูลและกลับสู่ข้อมูลเริ่มต้น

ก่อนทดสอบแต่ละเรื่อง ควรเริ่มจากข้อมูลเริ่มต้นเสมอ เพื่อให้ผลทดสอบทำซ้ำได้ ผู้ตรวจสอบรายงานของผู้อื่นต้องเริ่มจากข้อมูลเริ่มต้นเช่นกัน

### วิธีที่ 1: เรียก API reset (เร็วที่สุด ไม่ต้องหยุดระบบ)

```bash
curl -X POST http://localhost:8001/api/reset
```

บน Windows (PowerShell) ใช้ `curl.exe -X POST http://localhost:8001/api/reset` หรือ Invoke-RestMethod ก็ได้ คำสั่งนี้ไม่ต้องยืนยันตัวตน และตอบกลับ `{"status":"reset","reset_at":"<เวลา>"}`

ผลของการ reset
- ข้อมูลทุกตารางกลับเป็นข้อมูลเริ่มต้น (ผู้ใช้ สินค้า คูปอง คำสั่งซื้อ รีวิว ที่อยู่ ตะกร้า รายการโปรด ประวัติสต็อก รายงานรายช่วงเวลา และประวัติการรันงาน)
- บัญชีที่สมัครเองหายไป
- โทเคนทั้งหมดใช้ไม่ได้ ต้องเข้าสู่ระบบใหม่ และตัวนับการล็อกบัญชีกลับเป็น 0
- ข้อมูลเริ่มต้นที่อ้างอิงเวลา (คูปอง `SOON3`, `LATER10` และเวลาของคำสั่งซื้อเริ่มต้น) ถูกคำนวณใหม่จากเวลาที่ reset

### วิธีที่ 2: ลบ volume ของฐานข้อมูล

```bash
docker compose down -v
docker compose up -d
```

`-v` ลบ volume `dojo-data` ที่เก็บฐานข้อมูล เมื่อเริ่มระบบใหม่ ระบบสร้างฐานข้อมูลและข้อมูลเริ่มต้นใหม่ทั้งหมด

### วิธีที่ 3: ล้างทั้งหมดและสร้างภาพใหม่

ใช้เมื่อสงสัยว่าภาพที่สร้างไว้เก่าหรือเสียหาย

```bash
docker compose down -v --rmi local
docker compose up --build -d
```

## 6. การดูตารางในฐานข้อมูล (ไม่บังคับ)

ใช้ตรวจสอบข้อมูลหลังทดสอบ เช่น ตรวจจำนวนสต็อกหรือยอดที่บันทึกในคำสั่งซื้อ

```bash
docker compose --profile dbview up -d
```

เปิด `http://localhost:8081` เพื่อดูตารางและรันคำสั่ง SQL แบบอ่านอย่างเดียว เมื่อไม่ต้องการแล้ว

```bash
docker compose --profile dbview stop dbview
```

## 7. การเปลี่ยนพอร์ต

หากพอร์ตชนกับโปรแกรมอื่น แก้ไขไฟล์ `.env`

```
WEB_PORT=8000
API_PORT=8001
DBVIEW_PORT=8081
```

แล้วสั่ง `docker compose up -d` อีกครั้ง หลังเปลี่ยนพอร์ต ที่อยู่ของหน้าเว็บและ API เปลี่ยนตาม และการตั้งค่า Postman ต้องเปลี่ยนตามด้วย

## 8. การตรวจสอบเวอร์ชัน

เวอร์ชันของระบบที่กำลังทดสอบแสดงที่

- ส่วนท้ายของทุกหน้า: `DojoMart v{version} ({รหัสแฮช 8 ตัว})`
- `GET http://localhost:8001/api/version` ซึ่งให้ `version`, `source_hash` และ `started_at`

เมื่อรายงานข้อบกพร่อง ให้ระบุ `version` และ `source_hash` เสมอ ค่า `source_hash` คำนวณจากซอร์สโค้ดตอนสร้างภาพ หากแก้ไขซอร์สโค้ดในเครื่องของตน ค่านี้จะต่างไปจากเครื่องอื่น ดังนั้นการตรวจทำซ้ำ (reproduce) ต้องทำบนซอร์สโค้ดที่ไม่ถูกแก้ไข

## 9. ทางสำรอง: รันโดยไม่ใช้ Docker

ใช้เมื่อเครื่องไม่รองรับ Docker ต้องมี Python 3.12

```bash
cd app
python -m venv .venv
# macOS / Linux
source .venv/bin/activate
# Windows (PowerShell)  .venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

เปิด 3 หน้าต่างเทอร์มินัล (ทั้งหมดอยู่ในโฟลเดอร์ `app` และเปิดใช้ environment เดียวกัน)

```bash
python -m dojo.api        # API ที่พอร์ต 8001
python -m dojo.web        # หน้าเว็บที่พอร์ต 8000
python -m dojo.scheduler  # งานตั้งเวลา
```

ฐานข้อมูลถูกสร้างที่ `app/data/dojo.db` ล้างข้อมูลได้ด้วย `POST /api/reset` หรือลบไฟล์นั้นขณะหยุดระบบ ตัวแปรพอร์ตอ่านจาก `.env` เช่นเดียวกัน

## 10. การแก้ปัญหาเบื้องต้น

| อาการ | สาเหตุที่เป็นไปได้ | วิธีแก้ |
|---|---|---|
| `Cannot connect to the Docker daemon` | Docker ยังไม่เปิด | เปิด Docker Desktop และรอให้พร้อม |
| `port is already allocated` หรือ `address already in use` | พอร์ตถูกใช้อยู่ | เปลี่ยนพอร์ตใน `.env` (หัวข้อ 7) หรือปิดโปรแกรมที่ใช้พอร์ตนั้น |
| `unknown flag: --profile` หรือ `docker: 'compose' is not a docker command` | Docker Compose รุ่นเก่า | อัปเดต Docker เป็นรุ่นที่มี Compose v2 |
| บน Windows เริ่มระบบไม่ได้ | ยังไม่เปิด virtualization หรือ WSL 2 | เปิดใช้งานตามคู่มือของ Docker Desktop |
| บน Linux ได้ `permission denied` | ผู้ใช้ไม่อยู่ในกลุ่ม docker | เพิ่มผู้ใช้เข้ากลุ่ม `docker` หรือใช้ `sudo` |
| สร้างภาพไม่สำเร็จ | ไม่มีอินเทอร์เน็ตขณะดาวน์โหลดภาพพื้นฐาน | เชื่อมต่ออินเทอร์เน็ตแล้วสั่ง `docker compose up --build` ใหม่ |
| หน้าเว็บเปิดได้แต่ไม่มีข้อมูล หรือแสดงข้อผิดพลาดการเชื่อมต่อ | API ยังไม่พร้อมหรือพอร์ต API ถูกเปลี่ยน | ตรวจ `http://localhost:8001/api/health` รอสักครู่แล้วโหลดหน้าใหม่ ตรวจว่า `.env` ตรงกับพอร์ตที่ใช้ |
| ข้อมูลไม่ตรงกับเอกสารข้อมูลเริ่มต้น | ข้อมูลถูกแก้ไขจากการทดสอบก่อนหน้า | ล้างข้อมูลตามหัวข้อ 5 |
| เข้าสู่ระบบแล้วถูกพากลับหน้า Sign in ทันที | โทเคนหมดอายุ (อายุ 10 นาที) | เข้าสู่ระบบใหม่ |
| ใช้งานบน Apple Silicon (M1/M2/M3) | ไม่มีปัญหาที่ทราบ ภาพที่ใช้รองรับทั้งสองสถาปัตยกรรม | ไม่ต้องดำเนินการ |

## 11. ข้อควรปฏิบัติ

1. ระบบนี้มีข้อบกพร่องและจุดอ่อนด้านความปลอดภัยที่ตั้งใจให้มี **ห้ามเปิดพอร์ตให้เครื่องอื่นในเครือข่ายเข้าถึง** (ระบบผูกพอร์ตกับ `127.0.0.1` อยู่แล้ว ห้ามแก้ให้เปิดกว้างกว่านั้น)
2. ใช้เอกสารใน `docs/requirements/` และ `docs/design/` เป็นเกณฑ์ตัดสินว่าพฤติกรรมใดถูกต้อง
3. กติกาการรายงาน การตรวจ และการให้คะแนน เป็นไปตามที่ผู้สอนกำหนดในระบบรายงานของรายวิชา
