# PRD-REPORT: รายงานยอดขาย

## 1. ภาพรวม

ผู้จัดการและผู้ดูแลระบบดูรายงานสรุปยอดขาย สินค้าขายดี การใช้คูปอง และรายงานรายช่วงเวลาที่งานตั้งเวลาสร้างขึ้น รวมทั้งส่งออกเป็นไฟล์ CSV

## 2. ขอบเขต

**อยู่ในขอบเขต:** รายงานยอดขายตามช่วงวันที่ สินค้าขายดี การใช้คูปอง รายงานรายช่วงเวลา และการส่งออก CSV

**อยู่นอกขอบเขต:** กราฟ การส่งออกรูปแบบอื่นนอกจาก CSV และการตั้งเวลาส่งรายงานทางอีเมล

## 3. ข้อกำหนด

เฉพาะบทบาท `manager` และ `admin` ใช้ endpoint ในหัวข้อนี้ได้ บทบาทอื่นได้ 403 `FORBIDDEN`

**กฎทั่วไปของพารามิเตอร์วันที่** (รายงานที่ใช้ `from` และ `to` แบบวันที่ล้วน)

- `from` และ `to` จำเป็น รูปแบบ `YYYY-MM-DD` เป็นวันที่ที่มีอยู่จริง มิฉะนั้นตอบ 400 `VALIDATION_ERROR`
- `from` ต้องไม่หลัง `to` มิฉะนั้นตอบ 400 `VALIDATION_ERROR` ข้อความ `Start date must not be after end date.`
- ช่วงวันที่ (นับรวมวันแรกและวันสุดท้าย) ต้องไม่เกิน 366 วัน มิฉะนั้นตอบ 400 `VALIDATION_ERROR`
- ช่วงรวมทั้งวัน `from` และวัน `to` ตามเวลาประเทศไทย

คำสั่งซื้อที่นับในรายงานเป็นไปตาม `REQ-CROSS-006` โดยวันที่ของคำสั่งซื้อคือวันที่ของ `paid_at` ตามเวลาประเทศไทย

### REQ-RPT-001: รายงานสรุปยอดขาย

`GET /api/manage/reports/sales?from=&to=` ตอบ 200 ในรูป

```json
{
  "from": "2026-10-04", "to": "2026-10-10",
  "order_count": 5,
  "gross_sales": "5230.40",
  "vat_total": "342.10",
  "shipping_total": "150.00",
  "discount_total": "412.30",
  "average_order_value": "1046.08",
  "daily": [ { "date": "2026-10-04", "order_count": 0, "gross_sales": "0.00",
               "vat_total": "0.00", "shipping_total": "0.00", "discount_total": "0.00" } ]
}
```

| ฟิลด์ | นิยาม |
|---|---|
| `order_count` | จำนวนคำสั่งซื้อที่นับในช่วงวันที่ |
| `gross_sales` | ผลรวมของ `grand_total` ของคำสั่งซื้อเหล่านั้น |
| `vat_total` | ผลรวมของ VAT ที่บันทึกในแต่ละคำสั่งซื้อ (ไม่คำนวณใหม่จากยอดรวม) |
| `shipping_total` | ผลรวมของค่าจัดส่ง |
| `discount_total` | ผลรวมของ (ส่วนลดตามยอด + ส่วนลดคูปอง) |
| `average_order_value` | `gross_sales` หารด้วย `order_count` ปัดเศษ half-up เป็น 2 ตำแหน่ง และเป็น `"0.00"` เมื่อ `order_count` เป็น 0 (ต้องไม่เกิดข้อผิดพลาด) |
| `daily` | รายการของ **ทุกวัน** ในช่วง เรียงจากวันที่เก่าไปใหม่ รวมวันที่ไม่มีคำสั่งซื้อ (ค่าเป็นศูนย์) |

ผลรวมของทุกแถวใน `daily` ต้องเท่ากับค่ารวมของฟิลด์ที่ตรงกัน

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-RPT-001.1 | ไม่มีคำสั่งซื้อที่นับในช่วงที่เลือก | ขอรายงาน | ได้ 200 `order_count` เป็น 0 และ `average_order_value` เป็น `"0.00"` |
| AC-RPT-001.2 | ช่วงที่เลือกมีคำสั่งซื้อที่นับ 2 รายการ โดย `gross_sales` รวมเป็น 100.01 | ขอรายงาน | `average_order_value` เป็น `"50.01"` (50.005 ปัดขึ้น) |
| AC-RPT-001.3 | คำสั่งซื้อถูกยกเลิก | ขอรายงานของวันที่ชำระเงิน | คำสั่งซื้อนั้นไม่ถูกนับ |
| AC-RPT-001.4 | คำสั่งซื้อชำระเงินเวลา 23:30 (เวลาไทย) ของวันที่ D | ขอรายงานวันที่ D | คำสั่งซื้อนั้นถูกนับในวันที่ D (ไม่ใช่วันถัดไป) |

### REQ-RPT-002: รายงานสินค้าขายดี

`GET /api/manage/reports/top-products?from=&to=&limit=` ตอบ 200 ในรูป `{ "items": [ { "product_id", "sku", "name", "quantity", "revenue" } ] }`

- `limit` เป็นจำนวนเต็ม 1 ถึง 20 ค่าเริ่มต้น 5
- จัดอันดับตามผลรวมจำนวนชิ้นที่ขายได้ (`quantity`) จากมากไปน้อย หากเท่ากันเรียงตามชื่อสินค้า (ไม่แยกตัวพิมพ์) จากน้อยไปมาก และหากยังเท่ากันเรียงตาม `product_id`
- `revenue` คือผลรวมของ `line_total` ของสินค้านั้น (ก่อนหักส่วนลดระดับคำสั่งซื้อ ไม่รวม VAT และค่าจัดส่ง)
- `name` คือชื่อปัจจุบันของสินค้า

### REQ-RPT-003: รายงานการใช้คูปอง

`GET /api/manage/reports/coupon-usage?from=&to=` ตอบ 200 ในรูป `{ "items": [ { "code", "order_count", "discount_total" } ] }` สำหรับคูปองที่ถูกใช้ในคำสั่งซื้อที่นับ โดย `discount_total` คือผลรวมของส่วนลดคูปองเท่านั้น (ไม่รวมส่วนลดตามยอด) เรียงตาม `discount_total` จากมากไปน้อย และหากเท่ากันเรียงตาม `code`

### REQ-RPT-004: รายงานรายช่วงเวลา (จากงานตั้งเวลา)

`GET /api/manage/reports/hourly?from=&to=` คืนแถวรายงานที่งาน `hourly-sales-report` สร้างไว้ (ดู `REQ-SCH-003`)

- `from` และ `to` เป็นเวลาระดับนาทีตามรูปแบบเวลาของคูปอง (เช่น `2026-10-10T14:00+07:00`) มีวินาทีไม่ได้ `from` ต้องไม่หลัง `to` และช่วงต้องไม่เกิน 7 วัน
- คืนแถวที่ `window_start` อยู่ในช่วง `[from, to]` เรียงตาม `window_start` จากเก่าไปใหม่
- แต่ละแถวมี `window_start`, `window_end`, `order_count`, `gross_sales`, `vat_total`, `shipping_total`, `discount_total`, `generated_at`
- ค่าในแต่ละแถวต้องตรงกับผลรวมของคำสั่งซื้อที่ `paid_at` อยู่ในช่วง `[window_start, window_end)` ณ เวลาที่สร้างรายงาน

### REQ-RPT-005: การส่งออก CSV

มี 3 endpoint: `GET /api/manage/reports/sales.csv`, `GET /api/manage/reports/top-products.csv`, `GET /api/manage/reports/hourly.csv` ใช้พารามิเตอร์และกฎการตรวจสอบเหมือนรายงานที่ตรงกัน

| รูปแบบไฟล์ | กฎ |
|---|---|
| การเข้ารหัส | UTF-8 ไม่มี BOM |
| ตัวคั่นฟิลด์ | จุลภาค `,` |
| ตัวคั่นบรรทัด | CRLF (`\r\n`) |
| บรรทัดแรก | หัวคอลัมน์ |
| การครอบด้วยเครื่องหมายคำพูด | ฟิลด์ที่มีจุลภาค เครื่องหมายคำพูด หรือขึ้นบรรทัดใหม่ ต้องครอบด้วย `"` และเครื่องหมาย `"` ภายในต้องซ้ำเป็น `""` (ตาม RFC 4180) |
| จำนวนเงิน | ทศนิยม 2 ตำแหน่ง ใช้จุดเป็นตัวคั่นทศนิยม ไม่มีตัวคั่นหลักพัน ไม่มีสัญลักษณ์สกุลเงิน |
| เวลา | ISO 8601 พร้อม `+07:00` |

| endpoint | คอลัมน์ (ตามลำดับ) | แถว |
|---|---|---|
| `sales.csv` | `date,order_count,gross_sales,vat_total,shipping_total,discount_total` | หนึ่งแถวต่อวัน ตามแถวใน `daily` |
| `top-products.csv` | `rank,product_id,sku,name,quantity,revenue` | หนึ่งแถวต่อสินค้า โดย `rank` เริ่มที่ 1 |
| `hourly.csv` | `window_start,window_end,order_count,gross_sales,vat_total,shipping_total,discount_total` | หนึ่งแถวต่อแถวรายงาน |

ส่วนหัวของการตอบกลับเป็นไปตาม `REQ-COM-010` โดยชื่อไฟล์ใน `Content-Disposition` คือ

| endpoint | ชื่อไฟล์ |
|---|---|
| `sales.csv` | `sales-report_{from}_{to}.csv` |
| `top-products.csv` | `top-products_{from}_{to}.csv` |
| `hourly.csv` | `window-report_{from}_{to}.csv` โดย `{from}` และ `{to}` อยู่ในรูป `YYYYMMDDTHHmm` |

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-RPT-005.1 | สินค้าชื่อ `Notebook, A5 (Lined)` ถูกขายในช่วงที่เลือก | ส่งออก `top-products.csv` | ฟิลด์ชื่อสินค้าถูกครอบด้วย `"` และจำนวนคอลัมน์ของแถวนั้นยังเท่ากับหัวคอลัมน์ |

### REQ-RPT-006: ความสอดคล้องของรายงาน

- ผลรวมในรายงานต้องตรงกับผลรวมของคำสั่งซื้อที่นับจริงในช่วงเดียวกัน
- รายงานสรุป ยอดรวมรายวัน และไฟล์ CSV ของช่วงเดียวกัน ต้องให้ตัวเลขตรงกัน

### REQ-RPT-007: หน้าจอ Reports

หน้า `/manager/reports` มีแท็บ Sales, Top products, Coupons, Window reports ช่องเลือกวันที่เริ่มต้นกำหนดเป็น 7 วันล่าสุด (วันที่สิ้นสุดเป็นวันนี้ วันที่เริ่มเป็นวันนี้ลบ 6 วัน) ปุ่ม Export CSV (ยกเว้นแท็บ Coupons) และเมื่อไม่มีข้อมูลแสดง `No data for the selected period.` จำนวนเงินแสดงรูปแบบ `฿1,234.50` และจัดชิดขวา
