# PRD-ADMIN: การจัดการผู้ใช้

## 1. ภาพรวม

ผู้ดูแลระบบค้นหาและจัดการบัญชีผู้ใช้ ได้แก่ การล็อกและปลดล็อกบัญชี การรีเซ็ตรหัสผ่าน และการเปลี่ยนบทบาท

## 2. ขอบเขต

**อยู่ในขอบเขต:** รายการผู้ใช้ การล็อก การปลดล็อก การรีเซ็ตรหัสผ่าน การเปลี่ยนบทบาท และมาตรการป้องกันที่เกี่ยวข้อง

**อยู่นอกขอบเขต:** การลบบัญชี การสร้างบัญชีโดยผู้ดูแลระบบ และการแก้ไขข้อมูลส่วนตัวของผู้อื่น

## 3. ข้อกำหนด

เฉพาะบทบาท `admin` ใช้ endpoint ในหัวข้อนี้ได้ บทบาทอื่นได้ 403 `FORBIDDEN`

### REQ-ADM-001: รายการผู้ใช้

`GET /api/admin/users` รองรับพารามิเตอร์ `q`, `role`, `page`, `page_size`

- `q` ถูกตัดช่องว่างหน้า-หลัง และตรงกับผู้ใช้ที่ `username` หรือ `display_name` มีข้อความ `q` เป็นส่วนหนึ่ง โดยไม่แยกตัวพิมพ์ใหญ่-เล็ก
- `role` ต้องเป็นหนึ่งใน `customer`, `staff`, `manager`, `admin` มิฉะนั้นตอบ 400 `VALIDATION_ERROR` ตัวกรองและ `q` ทำงานร่วมกันแบบ "และ"
- เรียงตาม `username` (ไม่แยกตัวพิมพ์) จากน้อยไปมาก และหากเท่ากันเรียงตาม `id` แบ่งหน้าตาม `REQ-COM-011`
- แต่ละรายการมี `id`, `username`, `display_name`, `role`, `status` (`ACTIVE` หรือ `LOCKED`), `temporarily_locked` (จริงเมื่อบัญชีถูกล็อกชั่วคราวและยังไม่พ้นเวลา), `created_at`

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-ADM-001.1 | มีผู้ใช้ `staff1`, `staff2`, `staff3` และบัญชีอื่น | `admin1` กรอง `role=staff` | พบเฉพาะผู้ใช้บทบาท `staff` ทั้งสามบัญชี |
| AC-ADM-001.2 | ข้อมูลเริ่มต้น | `admin1` ค้นหา `CUST` | พบผู้ใช้ที่ `username` ขึ้นต้นด้วย `customer` ทั้งสามบัญชี (การค้นหาไม่แยกตัวพิมพ์ใหญ่-เล็ก) |

### REQ-ADM-002: การล็อกบัญชี

`POST /api/admin/users/{id}/lock` ตอบ 200 พร้อมข้อมูลผู้ใช้

- สถานะบัญชีเป็น `LOCKED` และโทเคนทั้งหมดของบัญชีนั้นใช้ไม่ได้ทันที (ตาม `REQ-CROSS-007`) การเข้าสู่ระบบถูกปฏิเสธตาม `REQ-AUTH-005`
- ผู้ดูแลระบบล็อกบัญชีของตนเองไม่ได้ ตอบ 409 `SELF_LOCK_FORBIDDEN`
- ห้ามล็อกผู้ดูแลระบบที่ยังไม่ถูกล็อกคนสุดท้ายที่เหลืออยู่ ตอบ 409 `LAST_ADMIN`
- บัญชีที่ถูกล็อกอยู่แล้ว ตอบ 409 `ACCOUNT_ALREADY_LOCKED`
- ผู้ใช้ที่ไม่มีอยู่ ตอบ 404 `NOT_FOUND`
- ลำดับการตรวจ: 404 → `SELF_LOCK_FORBIDDEN` → `ACCOUNT_ALREADY_LOCKED` → `LAST_ADMIN`

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-ADM-002.1 | `customer1` ถือโทเคนที่ใช้ได้ | `admin1` ล็อก `customer1` แล้ว `customer1` เรียก `GET /api/me` ด้วยโทเคนเดิม | ล็อกได้ 200 และ `GET /api/me` ได้ 401 |
| AC-ADM-002.2 | `admin1` ล็อกอินอยู่ | `admin1` ล็อกบัญชีของตนเอง | ได้ 409 `SELF_LOCK_FORBIDDEN` |

### REQ-ADM-003: การปลดล็อกบัญชี

`POST /api/admin/users/{id}/unlock` ตอบ 200 พร้อมข้อมูลผู้ใช้

- ใช้ได้กับบัญชีที่มีสถานะ `LOCKED` หรือที่ถูกล็อกชั่วคราวอยู่ มิฉะนั้นตอบ 409 `ACCOUNT_NOT_LOCKED`
- เมื่อสำเร็จ สถานะเป็น `ACTIVE` ตัวนับการเข้าสู่ระบบผิดกลับเป็น 0 และการล็อกชั่วคราวถูกยกเลิก ผู้ใช้เข้าสู่ระบบได้ทันที

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-ADM-003.1 | บัญชี `customer3` ถูกล็อกชั่วคราวจากการเข้าสู่ระบบผิด 5 ครั้ง | `admin1` ปลดล็อก แล้ว `customer3` เข้าสู่ระบบด้วยรหัสผ่านที่ถูกต้อง | เข้าสู่ระบบได้ 200 |
| AC-ADM-003.2 | บัญชี `customer3` ถูกปลดล็อกแล้วหลังเคยผิด 4 ครั้ง | `customer3` เข้าสู่ระบบผิดอีก 4 ครั้ง | ไม่ถูกล็อก (ตัวนับเริ่มใหม่) |

### REQ-ADM-004: การรีเซ็ตรหัสผ่าน

`POST /api/admin/users/{id}/reset-password` ตอบ 200 พร้อม `{ "temporary_password": "<รหัสผ่านชั่วคราว>" }`

- รหัสผ่านชั่วคราวยาว 12 อักขระ ประกอบด้วยตัวอักษรละตินและตัวเลข มีทั้งสองชนิด ผ่านกฎรหัสผ่านของระบบ และสุ่มใหม่ทุกครั้ง
- ระบบตั้งสถานะ "ต้องเปลี่ยนรหัสผ่าน" ให้บัญชี (ตาม `REQ-AUTH-009`) ยกเลิกโทเคนทั้งหมดของบัญชี และรีเซ็ตตัวนับการเข้าสู่ระบบผิดกับการล็อกชั่วคราว
- รหัสผ่านชั่วคราวแสดงให้ผู้ดูแลระบบเห็นเพียงครั้งเดียวและระบบไม่เก็บเป็นข้อความตรง

### REQ-ADM-005: การเปลี่ยนบทบาท

`PATCH /api/admin/users/{id}/role` รับ `role` ตอบ 200 พร้อมข้อมูลผู้ใช้

- `role` ต้องเป็นหนึ่งใน `customer`, `staff`, `manager`, `admin` มิฉะนั้นตอบ 400 `VALIDATION_ERROR`
- การเปลี่ยนเป็นบทบาทเดิมตอบ 200 โดยไม่เปลี่ยนแปลงอะไร
- ห้ามเปลี่ยนบทบาทของผู้ดูแลระบบที่ยังไม่ถูกล็อกคนสุดท้ายที่เหลืออยู่ให้เป็นบทบาทอื่น ตอบ 409 `LAST_ADMIN` ผู้ดูแลระบบเปลี่ยนบทบาทของตนเองได้ หากยังมีผู้ดูแลระบบที่ไม่ถูกล็อกคนอื่นเหลืออยู่
- บทบาทใหม่มีผลกับโทเคนเดิมตั้งแต่คำขอถัดไป (ตาม `REQ-CROSS-007`)
- ข้อมูลของผู้ใช้ (ตะกร้า คำสั่งซื้อ ที่อยู่) คงอยู่ตามเดิมเมื่อเปลี่ยนบทบาท

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-ADM-005.1 | `manager1` ถือโทเคนที่ใช้ได้ และเรียก `GET /api/manage/reports/sales` ได้ | `admin1` เปลี่ยนบทบาท `manager1` เป็น `customer` แล้ว `manager1` เรียก `GET /api/manage/reports/sales` ด้วยโทเคนเดิม | ได้ 403 `FORBIDDEN` |
| AC-ADM-005.2 | เหลือผู้ดูแลระบบที่ไม่ถูกล็อกเพียง `admin1` | `admin1` เปลี่ยนบทบาทของตนเองเป็น `staff` | ได้ 409 `LAST_ADMIN` |

### REQ-ADM-006: หน้าจอ User management

หน้า `/admin/users` แสดงตารางผู้ใช้ ช่องค้นหา ตัวกรองบทบาท ป้ายสถานะ `Active`, `Locked`, `Temporarily locked` และปุ่ม Lock/Unlock, Reset password, Change role ต่อแถว ทุกการดำเนินการต้องมีการยืนยันก่อน และรหัสผ่านชั่วคราวแสดงในกล่องข้อความพร้อมคำเตือนว่าจะแสดงเพียงครั้งเดียว

## 4. สมมติฐาน

- ข้อมูลเริ่มต้นมีผู้ดูแลระบบ 3 บัญชี (`admin1` ถึง `admin3`)
