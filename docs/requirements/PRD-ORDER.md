# PRD-ORDER: การสั่งซื้อ การชำระเงิน และการดำเนินการคำสั่งซื้อ

## 1. ภาพรวม

ลูกค้าสร้างคำสั่งซื้อจากตะกร้า ชำระเงิน (จำลอง) ติดตามสถานะ ยกเลิก หรือคืนสินค้าภายในระยะเวลาที่กำหนด เจ้าหน้าที่และผู้ดูแลระบบดำเนินการคำสั่งซื้อตามขั้นตอนจนส่งมอบ

## 2. ขอบเขต

**อยู่ในขอบเขต:** การสร้างคำสั่งซื้อ การชำระเงินจำลอง วงจรสถานะ การยกเลิก การคืนสินค้า รายการคำสั่งซื้อของลูกค้า และคิวคำสั่งซื้อของเจ้าหน้าที่

**อยู่นอกขอบเขต:** การเชื่อมต่อผู้ให้บริการชำระเงินจริง ใบกำกับภาษี การติดตามพัสดุ การคืนสินค้าบางส่วน และการคืนเงินจริง (ระบบเพียงบันทึกจำนวนเงินที่คืน)

## 3. ข้อกำหนด

### โครงสร้างข้อมูลคำสั่งซื้อ

`GET /api/orders/{id}` คืนข้อมูลคำสั่งซื้อในรูปแบบต่อไปนี้ (ตัวอย่างย่อ)

```json
{
  "id": 9,
  "status": "PENDING_PAYMENT",
  "customer": { "id": 2, "username": "customer2", "display_name": "Malee Rakdee" },
  "items": [ { "product_id": 1, "sku": "DM-1001", "name": "Ceramic Coffee Mug",
               "unit_price": "129.00", "quantity": 2, "line_total": "258.00" } ],
  "coupon_code": null,
  "pricing": { "subtotal": "258.00", "volume_discount": "0.00", "coupon_discount": "0.00",
               "goods_total": "258.00", "vat": "18.06", "shipping": "50.00", "grand_total": "326.06" },
  "address": { "label": "Home", "recipient_name": "Malee Rakdee", "phone": "0898765432",
               "line1": "99/9 Sukhumvit Rd", "line2": null, "province": "Bangkok", "postal_code": "10110" },
  "refund_amount": "0.00",
  "created_at": "2026-10-10T14:00:00+07:00",
  "paid_at": null, "packed_at": null, "shipped_at": null, "delivered_at": null,
  "cancelled_at": null, "returned_at": null,
  "return_deadline": null
}
```

`return_deadline` มีค่าเมื่อสถานะเป็น `DELIVERED` เท่ากับ `delivered_at` บวก 7 วัน (168 ชั่วโมง) มิฉะนั้นเป็น `null`

### REQ-ORD-001: การสร้างคำสั่งซื้อ

`POST /api/orders` รับ `address_id` เฉพาะบทบาท `customer` ใช้ได้ ตอบ 201 พร้อมข้อมูลคำสั่งซื้อ

- ลำดับการตรวจ
  1. `address_id` ต้องเป็นจำนวนเต็ม มิฉะนั้นตอบ 400 `VALIDATION_ERROR`
  2. `address_id` ต้องเป็นที่อยู่ของผู้เรียก มิฉะนั้นตอบ 404 `NOT_FOUND`
  3. ตะกร้าต้องมีรายการ มิฉะนั้นตอบ 409 `CART_EMPTY`
  4. สต็อกของทุกรายการต้องเพียงพอต่อจำนวนในตะกร้า มิฉะนั้นตอบ 409 `INSUFFICIENT_STOCK`
  5. หากมีคูปองในตะกร้า ต้องผ่านเงื่อนไขตาม `REQ-COUP-007` มิฉะนั้นตอบ 409 `COUPON_INVALID`
- เมื่อผ่านการตรวจ ระบบต้องดำเนินการต่อไปนี้ภายใต้ธุรกรรมเดียว (สำเร็จทั้งหมดหรือไม่เกิดขึ้นเลย)
  - สร้างคำสั่งซื้อสถานะ `PENDING_PAYMENT` พร้อมข้อมูลที่บันทึกตาม `REQ-CROSS-003`
  - ลดสต็อกของแต่ละรายการตามจำนวนที่สั่ง และบันทึกรายการเคลื่อนไหวเหตุผล `ORDER`
  - ล้างตะกร้า (รายการและคูปอง)
- การส่งคำขอสร้างคำสั่งซื้อซ้ำจากตะกร้าใบเดิม (เช่น กดปุ่มซ้ำ) ต้องไม่สร้างคำสั่งซื้อซ้ำ คำขอหลังต้องได้ 409 `CART_EMPTY`

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-ORD-001.1 | `customer3` มีตะกร้าที่มี Ceramic Coffee Mug ×2 และมีที่อยู่ | สั่งซื้อ | ได้ 201 สถานะ `PENDING_PAYMENT` สต็อก Ceramic Coffee Mug ลดลง 2 และตะกร้าว่าง |
| AC-ORD-001.2 | ตะกร้าว่าง | สั่งซื้อ | ได้ 409 `CART_EMPTY` |
| AC-ORD-001.3 | ลูกค้ามีตะกร้าที่ใช้ได้ | ส่งคำขอสั่งซื้อสองครั้งติดกัน | ครั้งแรกได้ 201 ครั้งที่สองได้ 409 `CART_EMPTY` และมีคำสั่งซื้อใหม่เพียง 1 รายการ |
| AC-ORD-001.4 | ตะกร้ามีสินค้า Limited Edition Notebook ×1 ซึ่งสต็อกเหลือ 1 | ลูกค้า 2 คนที่มีสินค้านี้ในตะกร้าสั่งซื้อพร้อมกัน | สำเร็จเพียงคนเดียว อีกคนได้ 409 `INSUFFICIENT_STOCK` และสต็อกเป็น 0 ไม่ติดลบ |

### REQ-ORD-002: ข้อมูลที่บันทึกในคำสั่งซื้อ

เป็นไปตาม `REQ-CROSS-003` และ `REQ-CROSS-001` ยอดทุกส่วนประกอบของราคาในคำสั่งซื้อต้องตรงกับที่ตะกร้าแสดงก่อนสั่งซื้อ รวมส่วนลดคูปองด้วย

### REQ-ORD-003: การชำระเงิน (จำลอง)

`POST /api/orders/{id}/pay` รับ `method` เป็น `CARD` หรือ `PROMPTPAY`

- เฉพาะเจ้าของคำสั่งซื้อที่เป็น `customer` ทำได้ (บทบาทอื่นได้ 403 คำสั่งซื้อของผู้อื่นได้ 404)
- ค่า `method` อื่นตอบ 400 `VALIDATION_ERROR`
- คำสั่งซื้อต้องเป็นสถานะ `PENDING_PAYMENT` มิฉะนั้นตอบ 409 `INVALID_TRANSITION`
- เมื่อสำเร็จ สถานะเป็น `PAID` และบันทึก `paid_at` ตอบ 200 พร้อมคำสั่งซื้อ ระบบไม่เชื่อมต่อการชำระเงินจริงและการชำระเงินจำลองสำเร็จเสมอ

### REQ-ORD-004: วงจรสถานะ

ระบบอนุญาตเฉพาะการเปลี่ยนสถานะตามตารางต่อไปนี้ การเปลี่ยนสถานะอื่นทั้งหมดต้องตอบ 409 `INVALID_TRANSITION`

| จาก | ไป | ผู้ดำเนินการที่ได้รับอนุญาต | ช่องทาง |
|---|---|---|---|
| `PENDING_PAYMENT` | `PAID` | `customer` เจ้าของ | `POST /api/orders/{id}/pay` |
| `PENDING_PAYMENT` | `CANCELLED` | `customer` เจ้าของ, `staff`, `admin`, งานตั้งเวลา | `POST /api/orders/{id}/cancel` |
| `PAID` | `CANCELLED` | `customer` เจ้าของ, `staff`, `admin` | `POST /api/orders/{id}/cancel` |
| `PAID` | `PACKED` | `staff`, `admin` | `PATCH /api/manage/orders/{id}/status` |
| `PACKED` | `CANCELLED` | `staff`, `admin` เท่านั้น | `POST /api/orders/{id}/cancel` |
| `PACKED` | `SHIPPED` | `staff`, `admin` | `PATCH /api/manage/orders/{id}/status` |
| `SHIPPED` | `DELIVERED` | `staff`, `admin` | `PATCH /api/manage/orders/{id}/status` |
| `DELIVERED` | `RETURNED` | `customer` เจ้าของ | `POST /api/orders/{id}/return` |

- สถานะ `CANCELLED` และ `RETURNED` เป็นสถานะสุดท้าย ไม่เปลี่ยนไปสถานะอื่นอีก
- การเปลี่ยนสถานะแต่ละครั้งต้องบันทึกเวลาที่เกิดขึ้นในฟิลด์ที่ตรงกัน (`paid_at`, `packed_at`, `shipped_at`, `delivered_at`, `cancelled_at`, `returned_at`)
- ข้อความของ 409 `INVALID_TRANSITION` คือ `This order cannot be changed from its current status.`

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-ORD-004.1 | คำสั่งซื้อสถานะ `PAID` | `staff1` เปลี่ยนเป็น `DELIVERED` โดยตรง | ได้ 409 `INVALID_TRANSITION` |
| AC-ORD-004.2 | คำสั่งซื้อสถานะ `PAID` | `staff1` เปลี่ยนเป็น `PACKED` | ได้ 200 และสถานะเป็น `PACKED` พร้อม `packed_at` |
| AC-ORD-004.3 | คำสั่งซื้อสถานะ `SHIPPED` | ลูกค้าเจ้าของส่งคำขอยกเลิก | ได้ 409 `INVALID_TRANSITION` |

### REQ-ORD-005: การยกเลิกคำสั่งซื้อ

`POST /api/orders/{id}/cancel` ไม่มีเนื้อหาคำขอ ตอบ 200 พร้อมคำสั่งซื้อ

- ผู้ที่ยกเลิกได้และสถานะที่ยกเลิกได้ เป็นไปตาม `REQ-ORD-004` ลูกค้าที่ไม่ใช่เจ้าของได้ 404 บทบาท `manager` ได้ 403
- เมื่อยกเลิกสำเร็จ
  - สถานะเป็น `CANCELLED` และบันทึก `cancelled_at`
  - คืนสต็อกของทุกรายการตามจำนวนที่สั่ง และบันทึกรายการเคลื่อนไหวเหตุผล `CANCEL`
  - สิทธิ์การใช้คูปองของคำสั่งซื้อนี้กลับคืน ตาม `REQ-CROSS-005`
  - `refund_amount` เท่ากับยอดชำระสุทธิหากคำสั่งซื้อเคยอยู่ในสถานะ `PAID` หรือ `PACKED` และเป็น 0.00 หากยกเลิกตอน `PENDING_PAYMENT`
- การยกเลิกคำสั่งซื้อที่ถูกยกเลิกแล้วต้องตอบ 409 `INVALID_TRANSITION` และต้องไม่คืนสต็อกซ้ำ

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-ORD-005.1 | `customer2` มีคำสั่งซื้อสถานะ `PAID` ที่มีสินค้าชิ้นละ 2 ชิ้น | ยกเลิก | ได้ 200 สต็อกของสินค้านั้นเพิ่มขึ้น 2 และ `refund_amount` เท่ากับ `grand_total` |
| AC-ORD-005.2 | คำสั่งซื้อถูกยกเลิกแล้ว | ยกเลิกซ้ำ | ได้ 409 `INVALID_TRANSITION` และสต็อกไม่เปลี่ยน |

### REQ-ORD-006: การคืนสินค้า

`POST /api/orders/{id}/return` ไม่มีเนื้อหาคำขอ เฉพาะ `customer` เจ้าของ ตอบ 200 พร้อมคำสั่งซื้อ

- คำสั่งซื้อต้องเป็นสถานะ `DELIVERED` มิฉะนั้นตอบ 409 `INVALID_TRANSITION`
- เวลาปัจจุบันต้องไม่เกิน `return_deadline` (`delivered_at` บวก 7 วัน หรือ 168 ชั่วโมง) มิฉะนั้นตอบ 409 `RETURN_WINDOW_CLOSED` ข้อความ `The 7-day return period has ended.`
- เมื่อสำเร็จ สถานะเป็น `RETURNED` บันทึก `returned_at` และ `refund_amount` เท่ากับยอดชำระสุทธิเต็มจำนวน (รวม VAT และค่าจัดส่ง) คืนสต็อกของทุกรายการ และบันทึกรายการเคลื่อนไหวเหตุผล `RETURN`

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-ORD-006.1 | `customer2` มีคำสั่งซื้อที่ส่งมอบแล้วเมื่อ 6 วันก่อน | ขอคืนสินค้า | ได้ 200 สถานะ `RETURNED` และ `refund_amount` เท่ากับ `grand_total` |
| AC-ORD-006.2 | `customer2` มีคำสั่งซื้อที่ส่งมอบแล้วเมื่อ 8 วันก่อน | ขอคืนสินค้า | ได้ 409 `RETURN_WINDOW_CLOSED` |

### REQ-ORD-007: รายการและรายละเอียดคำสั่งซื้อของลูกค้า

- `GET /api/orders`: เฉพาะ `customer` คืนคำสั่งซื้อของผู้เรียกเท่านั้น เรียงจากใหม่ไปเก่า (เวลาสร้างมากไปน้อย ถ้าเท่ากันเรียง `id` มากไปน้อย) แบ่งหน้าตาม `REQ-COM-011` รองรับตัวกรอง `status` (ค่าต้องเป็นสถานะที่กำหนด มิฉะนั้น 400) แต่ละรายการมี `id`, `status`, `grand_total`, `created_at`, จำนวนรายการสินค้า (`item_count`)
- `GET /api/orders/{id}`: `customer` ดูได้เฉพาะของตนเอง (ของผู้อื่นได้ 404) ส่วน `staff` และ `admin` ดูได้ทุกคำสั่งซื้อ บทบาท `manager` ได้ 403

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-ORD-007.1 | `customer2` มีหลายคำสั่งซื้อ | เรียก `GET /api/orders` | คำสั่งซื้อเรียงจากใหม่ไปเก่า และเป็นของ `customer2` ทั้งหมด |

### REQ-ORD-008: คิวคำสั่งซื้อของเจ้าหน้าที่

- `GET /api/manage/orders`: เฉพาะ `staff` และ `admin` คืนคำสั่งซื้อของลูกค้าทุกคน เรียงและแบ่งหน้าเหมือน `REQ-ORD-007` รองรับตัวกรอง `status` และ `q`
- `q` ถูกตัดช่องว่างหน้า-หลัง และตรงกับคำสั่งซื้อที่เข้าเงื่อนไขข้อใดข้อหนึ่ง (1) `q` เป็นตัวเลขล้วนและเท่ากับรหัสคำสั่งซื้อ **ทั้งค่า** (2) ชื่อผู้ใช้ของลูกค้ามี `q` เป็นส่วนหนึ่งโดยไม่แยกตัวพิมพ์ใหญ่-เล็ก
- `PATCH /api/manage/orders/{id}/status` รับ `status` ได้เฉพาะ `PACKED`, `SHIPPED`, `DELIVERED` ค่าอื่นตอบ 400 `VALIDATION_ERROR` การเปลี่ยนที่ไม่เป็นไปตาม `REQ-ORD-004` ตอบ 409 `INVALID_TRANSITION` เมื่อสำเร็จตอบ 200 พร้อมคำสั่งซื้อ
- เจ้าหน้าที่ยกเลิกคำสั่งซื้อผ่าน `POST /api/orders/{id}/cancel` ตาม `REQ-ORD-005`

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-ORD-008.1 | มีคำสั่งซื้อรหัส 1 และรหัส 12 ซึ่งเป็นของ `customer2` และ `customer3` ตามลำดับ (ชื่อผู้ใช้ทั้งสองไม่มีเลข 1 และ `customer1` ไม่มีคำสั่งซื้อ) | `staff1` ค้นหา `q=1` | พบเฉพาะคำสั่งซื้อรหัส 1 และไม่พบรหัส 12 (รหัสต้องตรงกันทั้งค่า ไม่ใช่เพียงมีเลข 1 เป็นส่วนหนึ่ง) |
| AC-ORD-008.2 | `customer1` ล็อกอินแล้ว | เรียก `PATCH /api/manage/orders/1/status` | ได้ 403 `FORBIDDEN` |

### REQ-ORD-009: สต็อกและการทำงานพร้อมกัน

- สต็อกสินค้าต้องไม่ติดลบไม่ว่าจะมีคำสั่งซื้อเข้ามาพร้อมกันกี่รายการ
- เมื่อคำสั่งซื้อหลายรายการแย่งสต็อกชิ้นสุดท้าย ต้องสำเร็จเพียงรายการเดียวพอดี

### REQ-ORD-010: ความสอดคล้องของยอด

ยอดทุกส่วนประกอบที่ API ส่งออก ที่แสดงบนหน้าจอ และที่จัดเก็บในฐานข้อมูล ของคำสั่งซื้อเดียวกัน ต้องตรงกัน และ `grand_total` ต้องเท่ากับยอดสินค้า บวก VAT บวกค่าจัดส่งเสมอ

### REQ-ORD-011: หน้าจอที่เกี่ยวข้อง

- **Checkout (`/checkout`):** แสดงสรุปรายการและราคา และให้เลือกที่อยู่จัดส่ง (ที่อยู่หลักถูกเลือกไว้ล่วงหน้า) ปุ่ม Place order ต้องถูกปิดใช้งานระหว่างส่งคำขอ และเมื่อลูกค้าไม่มีที่อยู่ ต้องแสดง `Add a delivery address before placing an order.` พร้อมลิงก์ไปหน้า Profile ผู้ที่ตะกร้าว่างและเปิดหน้านี้ต้องถูกนำไปหน้า `/cart`
- **Order confirmation (`/orders/{id}/confirmation`):** แสดงข้อความสั่งซื้อสำเร็จ หมายเลขคำสั่งซื้อ สรุปราคา และปุ่ม Pay now พร้อมตัวเลือกวิธีชำระเงิน (สำหรับสถานะ `PENDING_PAYMENT`)
- **My orders (`/orders`) และ Order detail (`/orders/{id}`):** แสดงสถานะเป็นป้ายตามข้อความใน copy-deck เวลาในรูปแบบ `dd/MM/yyyy HH:mm` ปุ่ม Pay now (สถานะ `PENDING_PAYMENT`) ปุ่ม Cancel order (สถานะ `PENDING_PAYMENT` และ `PAID`) และปุ่ม Return order (สถานะ `DELIVERED` และยังไม่พ้น `return_deadline`) โดยการยกเลิกและการคืนสินค้าต้องมีการยืนยันก่อน
- **Order queue (`/staff/orders`):** ตารางคำสั่งซื้อ ช่องค้นหา ตัวกรองสถานะ ปุ่มดำเนินการถัดไปตามสถานะ (Mark as packed, Mark as shipped, Mark as delivered) และปุ่ม Cancel order สำหรับสถานะที่ยกเลิกได้

## 4. สมมติฐาน

- รหัสคำสั่งซื้อเป็นจำนวนเต็มที่ระบบออกให้เรียงต่อเนื่องและไม่ซ้ำ
- งานตั้งเวลายกเลิกคำสั่งซื้อที่ค้างชำระ กำหนดไว้ใน `PRD-SCHEDULE`
