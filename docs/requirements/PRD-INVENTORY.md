# PRD-INVENTORY: สต็อกสินค้าและประวัติการเคลื่อนไหว

## 1. ภาพรวม

เจ้าหน้าที่คลังและผู้ดูแลระบบดูและปรับจำนวนสต็อกสินค้า ระบบบันทึกประวัติการเคลื่อนไหวของสต็อกทุกครั้ง ทั้งจากการปรับด้วยตนเองและจากคำสั่งซื้อ การยกเลิก และการคืนสินค้า

## 2. ขอบเขต

**อยู่ในขอบเขต:** รายการสต็อก การปรับสต็อก ประวัติการเคลื่อนไหว และรายการสินค้าใกล้หมดจากงานตั้งเวลา

**อยู่นอกขอบเขต:** การสั่งซื้อสินค้าเข้าจากผู้ขาย สต็อกหลายคลัง และสต็อกแบบล็อตหรือวันหมดอายุ

## 3. ข้อกำหนด

เฉพาะบทบาท `staff` และ `admin` ใช้ endpoint ในหัวข้อนี้ได้ บทบาทอื่นได้ 403 `FORBIDDEN`

### REQ-INV-001: การปรับสต็อก

`POST /api/manage/inventory/adjustments` รับ `product_id`, `delta`, `reason` ตอบ 201 พร้อมรายการเคลื่อนไหวที่บันทึก

- สินค้าต้องมีอยู่ (รวมสินค้าที่ไม่ active) มิฉะนั้นตอบ 404 `NOT_FOUND`
- `delta` เป็นจำนวนเต็มที่ไม่เท่ากับ 0 และค่าสัมบูรณ์ไม่เกิน 100000 (ไม่รับทศนิยม)
- `reason` เป็นหนึ่งใน `RECEIVE` (รับของเข้า ต้องใช้ `delta` เป็นบวก), `DAMAGE` (ของเสียหาย ต้องใช้ `delta` เป็นลบ), `CORRECTION` (แก้ไขยอดนับ ใช้ `delta` บวกหรือลบก็ได้)
- ข้อมูลที่ไม่ตรงตามกฎข้างต้นตอบ 400 `VALIDATION_ERROR`
- สต็อกหลังปรับต้องไม่ติดลบ มิฉะนั้นตอบ 409 `STOCK_NEGATIVE` ข้อความ `Stock cannot be negative.` และไม่เปลี่ยนสต็อก
- เมื่อปรับสำเร็จ สต็อกที่ลูกค้าเห็นบนหน้าสินค้าต้องเป็นค่าใหม่ทันทีในคำขอถัดไป

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-INV-001.1 | สินค้า Throw Pillow มีสต็อก 18 | `staff1` ปรับ `delta` = -3 เหตุผล `DAMAGE` | ได้ 201 และสต็อกเป็น 15 |
| AC-INV-001.2 | สินค้า Limited Edition Notebook มีสต็อก 1 | ปรับ `delta` = -2 เหตุผล `CORRECTION` | ได้ 409 `STOCK_NEGATIVE` และสต็อกยังเป็น 1 |
| AC-INV-001.3 | ไม่มี | ปรับด้วย `delta` = 1.5 | ได้ 400 `VALIDATION_ERROR` |
| AC-INV-001.4 | ไม่มี | ปรับด้วย `delta` = -5 เหตุผล `RECEIVE` | ได้ 400 `VALIDATION_ERROR` |

### REQ-INV-002: ประวัติการเคลื่อนไหว

`GET /api/manage/inventory/movements` รองรับตัวกรอง `product_id` แบ่งหน้าตาม `REQ-COM-011` เรียงจากใหม่ไปเก่า (เวลาสร้างมากไปน้อย ถ้าเท่ากันเรียง `id` มากไปน้อย)

แต่ละรายการประกอบด้วย

| ฟิลด์ | ความหมาย |
|---|---|
| `id` | รหัสรายการ |
| `product_id`, `product_name` | สินค้า |
| `delta` | ปริมาณที่เปลี่ยน (บวกหรือลบ) |
| `stock_after` | สต็อกคงเหลือ **หลัง** การเปลี่ยนแปลงนี้ |
| `reason` | `RECEIVE`, `DAMAGE`, `CORRECTION`, `ORDER`, `CANCEL`, `RETURN` |
| `actor` | ชื่อผู้ใช้ของผู้ดำเนินการ หรือ `system` สำหรับงานตั้งเวลา |
| `created_at` | เวลาที่บันทึก |

ค่า `stock_after` ของรายการล่าสุดของสินค้าต้องเท่ากับสต็อกปัจจุบันของสินค้า และสำหรับรายการติดกันสองรายการของสินค้าเดียวกัน `stock_after` ของรายการใหม่เท่ากับ `stock_after` ของรายการก่อนหน้าบวก `delta` ของรายการใหม่

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-INV-002.1 | `staff2` ปรับสต็อกสินค้า X สำเร็จ | ดูประวัติของสินค้า X | รายการล่าสุดมี `actor` = `staff2` และ `stock_after` เท่ากับสต็อกปัจจุบัน |

### REQ-INV-003: การเคลื่อนไหวอัตโนมัติ

สต็อกที่เปลี่ยนจากการสั่งซื้อ การยกเลิก และการคืนสินค้า ต้องมีรายการเคลื่อนไหวตาม `REQ-CROSS-004`

### REQ-INV-004: รายการสินค้าใกล้หมด

- สินค้าใกล้หมดคือสินค้าที่ `active = true` และสต็อก **ไม่เกิน** 5
- `GET /api/manage/inventory/low-stock` คืนภาพถ่าย (snapshot) ล่าสุดที่งาน `low-stock-snapshot` บันทึก (ดู `REQ-SCH-004`) ในรูป `{ "taken_at": "<เวลา หรือ null>", "items": [ { "product_id", "sku", "name", "stock" } ] }`
- รายการเรียงตามสต็อกจากน้อยไปมาก ถ้าเท่ากันเรียงตามชื่อ (ไม่แยกตัวพิมพ์) จากนั้นด้วย `product_id`
- `taken_at` เป็น `null` และ `items` ว่าง หากยังไม่เคยมีการบันทึก snapshot

### REQ-INV-005: รายการสต็อก

`GET /api/manage/inventory` แสดงสินค้าทั้งหมดรวมที่ไม่ active ค้นหาด้วย `q` (ชื่อสินค้าเป็นส่วนหนึ่ง ไม่แยกตัวพิมพ์) เรียงตามชื่อ แบ่งหน้าตาม `REQ-COM-011` แต่ละรายการมี `product_id`, `sku`, `name`, `stock`, `active`

### REQ-INV-006: หน้าจอ

หน้า `/staff/inventory` แสดงตารางสต็อก ช่องค้นหา ปุ่ม Adjust stock (ฟอร์มกรอก `delta` และเลือก `reason`) และลิงก์ History ของแต่ละสินค้า หน้า `/staff/low-stock` แสดง snapshot พร้อมข้อความ `Snapshot taken at {dd/MM/yyyy HH:mm}`
