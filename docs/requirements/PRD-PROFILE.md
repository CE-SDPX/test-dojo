# PRD-PROFILE: โปรไฟล์และสมุดที่อยู่

## 1. ภาพรวม

ผู้ใช้ทุกบทบาทดูและแก้ไขข้อมูลโปรไฟล์ของตนเองได้ ส่วนลูกค้ามีเบอร์โทรและสมุดที่อยู่สำหรับจัดส่งเพิ่มเติม

## 2. ขอบเขต

**อยู่ในขอบเขต:** การดูและแก้ไขโปรไฟล์ การจัดการสมุดที่อยู่ของลูกค้า (เพิ่ม แก้ไข ลบ ตั้งเป็นที่อยู่หลัก)

**อยู่นอกขอบเขต:** การเปลี่ยนชื่อผู้ใช้ การเปลี่ยนวันเกิด การอัปโหลดรูปโปรไฟล์ การเปลี่ยนรหัสผ่าน (ดู `PRD-AUTH`)

## 3. ข้อกำหนด

### REQ-PROF-001: การดูและแก้ไขโปรไฟล์

- `GET /api/me` คืนข้อมูล `id`, `username`, `display_name`, `role`, `phone`, `birthdate`, `must_change_password`, `created_at` โดย `phone` และ `birthdate` มีค่าเฉพาะบทบาท `customer` (บทบาทอื่นเป็น `null`) และ `phone` เป็น `null` หากลูกค้ายังไม่ระบุ
- `PUT /api/me` แก้ไขได้เฉพาะ `display_name` (ทุกบทบาท) และ `phone` (เฉพาะ `customer`) ฟิลด์อื่นที่ส่งมาถูกละเว้น
- `display_name` ยาว 2 ถึง 50 อักขระหลังตัดช่องว่างหน้า-หลัง
- `phone` เป็นตัวเลข 10 หลักและขึ้นต้นด้วย `0` ลูกค้าลบเบอร์โทรได้โดยส่งสตริงว่างหรือ `null` สำหรับบทบาทอื่น ฟิลด์ `phone` ถูกละเว้น
- เมื่อสำเร็จ ตอบ 200 พร้อมข้อมูลโปรไฟล์ที่อัปเดตแล้ว

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-PROF-001.1 | `customer1` ล็อกอินแล้ว | บันทึกเบอร์โทร `0891234567` | ได้ 200 และ `phone` เป็น `0891234567` |
| AC-PROF-001.2 | เหมือนข้างต้น | บันทึกเบอร์โทร `891234567` | ได้ 400 `VALIDATION_ERROR` ที่ฟิลด์ `phone` |
| AC-PROF-001.3 | `staff1` ล็อกอินแล้ว | ส่ง `PUT /api/me` พร้อม `phone` | ได้ 200 และ `phone` ยังเป็น `null` |

### REQ-PROF-002: ข้อมูลที่อยู่

ที่อยู่แต่ละรายการมีฟิลด์ดังนี้ (ตัดช่องว่างหน้า-หลังทุกฟิลด์)

| ฟิลด์ | กฎ |
|---|---|
| `label` | จำเป็น 1 ถึง 30 อักขระ (เช่น Home, Office) |
| `recipient_name` | จำเป็น 2 ถึง 50 อักขระ |
| `phone` | จำเป็น ตัวเลข 10 หลัก ขึ้นต้นด้วย `0` |
| `line1` | จำเป็น 5 ถึง 100 อักขระ |
| `line2` | ไม่จำเป็น ไม่เกิน 100 อักขระ |
| `province` | จำเป็น 2 ถึง 50 อักขระ |
| `postal_code` | จำเป็น ตัวเลข 5 หลักพอดี |

- `POST /api/me/addresses` สร้างที่อยู่ ตอบ 201 พร้อมที่อยู่ที่สร้าง (มี `id`, `is_default`, `created_at`)
- `PUT /api/me/addresses/{id}` แก้ไขฟิลด์ทั้งหมดข้างต้น ตอบ 200 การแก้ไขไม่เปลี่ยนค่า `is_default`
- `GET /api/me/addresses` คืนรายการที่อยู่ทั้งหมดของผู้เรียก เรียงตามเวลาที่สร้างจากเก่าไปใหม่ (ถ้าเท่ากันเรียงตาม `id`) ในรูป `{ "items": [...] }` โดยไม่แบ่งหน้า

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-PROF-002.1 | `customer1` ล็อกอินแล้ว | สร้างที่อยู่ด้วยรหัสไปรษณีย์ `10110` และข้อมูลอื่นถูกต้อง | ได้ 201 |
| AC-PROF-002.2 | เหมือนข้างต้น | สร้างที่อยู่ด้วยรหัสไปรษณีย์ `1011` | ได้ 400 `VALIDATION_ERROR` ที่ฟิลด์ `postal_code` |

### REQ-PROF-003: จำนวนที่อยู่และที่อยู่หลัก

- ลูกค้าเก็บที่อยู่ได้สูงสุด 5 รายการ การสร้างรายการที่ 6 ต้องตอบ 409 `ADDRESS_LIMIT`
- ที่อยู่รายการแรกของลูกค้าต้องถูกตั้งเป็นที่อยู่หลัก (`is_default = true`) โดยอัตโนมัติ
- ลูกค้าที่มีที่อยู่อย่างน้อย 1 รายการ ต้องมีที่อยู่หลัก **เพียง 1 รายการ** เสมอ

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-PROF-003.1 | ลูกค้าที่ยังไม่มีที่อยู่ | สร้างที่อยู่แรก | ที่อยู่นั้นมี `is_default = true` |
| AC-PROF-003.2 | ลูกค้ามีที่อยู่ 5 รายการ | สร้างที่อยู่เพิ่ม | ได้ 409 `ADDRESS_LIMIT` |

### REQ-PROF-004: การตั้งที่อยู่หลัก

`POST /api/me/addresses/{id}/default` ตั้งที่อยู่นั้นเป็นที่อยู่หลัก ที่อยู่หลักเดิมต้องไม่เป็นที่อยู่หลักอีกต่อไป ตอบ 200 พร้อมที่อยู่ที่ถูกตั้ง

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-PROF-004.1 | `customer2` มีที่อยู่ 2 รายการ รายการ A เป็นที่อยู่หลัก | ตั้งรายการ B เป็นที่อยู่หลัก | B เป็นที่อยู่หลัก และ A ไม่เป็นที่อยู่หลัก |

### REQ-PROF-005: การลบที่อยู่

- `DELETE /api/me/addresses/{id}` ลบที่อยู่ ตอบ 204
- หากที่อยู่ที่ลบเป็นที่อยู่หลักและยังมีที่อยู่อื่นเหลืออยู่ ระบบต้องตั้งที่อยู่ที่ **สร้างเก่าที่สุด** ในบรรดาที่เหลือ (ถ้าเวลาสร้างเท่ากันให้ใช้ `id` น้อยที่สุด) เป็นที่อยู่หลักแทน
- หากไม่เหลือที่อยู่เลย ย่อมไม่มีที่อยู่หลัก
- การลบที่อยู่ต้องไม่กระทบคำสั่งซื้อที่เคยสร้างไว้แล้ว (คำสั่งซื้อเก็บสำเนาที่อยู่ ตาม `REQ-CROSS-003`)

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-PROF-005.1 | ลูกค้ามีที่อยู่ A (สร้างก่อน) B และ C โดย C เป็นที่อยู่หลัก | ลบ C | A กลายเป็นที่อยู่หลัก |

### REQ-PROF-006: สิทธิ์การเข้าถึงที่อยู่

- เฉพาะบทบาท `customer` ใช้ endpoint ของที่อยู่ได้ บทบาทอื่นได้ 403 `FORBIDDEN`
- ลูกค้าเข้าถึงได้เฉพาะที่อยู่ของตนเอง หากระบุ `id` ที่อยู่ของผู้อื่นหรือที่ไม่มีอยู่ ต้องได้ 404 `NOT_FOUND`

### REQ-PROF-007: หน้า Profile

- หน้า `/profile` ทุกบทบาทมีส่วน "Profile" (ชื่อผู้ใช้แสดงแบบอ่านอย่างเดียว ชื่อแสดงผลแก้ไขได้) และลิงก์ไปหน้า `/change-password`
- บทบาท `customer` มีช่องเบอร์โทร ข้อมูลวันเกิดแบบอ่านอย่างเดียว และส่วน "Addresses" ที่แสดงรายการที่อยู่ ป้ายกำกับ "Default" ที่ที่อยู่หลัก ปุ่ม Edit, Delete, Set as default และปุ่ม Add address (ซ่อนหรือปิดการใช้งานเมื่อมีครบ 5 รายการ)
- การลบที่อยู่ต้องมีการยืนยันก่อน
- ข้อความบนหน้าจอเป็นไปตาม `docs/design/ui/copy-deck.md`

## 4. สมมติฐาน
