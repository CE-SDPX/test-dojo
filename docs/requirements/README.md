# เอกสารข้อกำหนด (Requirements)

เอกสารในโฟลเดอร์นี้เป็นข้อกำหนดของระบบ DojoMart ในรูปแบบ PRD ซึ่งประกอบด้วยข้อกำหนด (REQ) และเกณฑ์การตรวจรับ (AC) ผู้ทดสอบใช้เอกสารเหล่านี้ร่วมกับเอกสารออกแบบใน `docs/design/` เป็นเกณฑ์ตัดสินว่าพฤติกรรมของระบบถูกต้องหรือไม่

## 1. หลักการใช้เอกสาร

1. **เอกสารเป็นเกณฑ์ตัดสิน** พฤติกรรมของระบบที่ไม่ตรงกับข้อกำหนดหรือเอกสารออกแบบถือเป็นข้อบกพร่อง
2. เอกสารเหล่านี้ถูกต้องและสอดคล้องกันทุกฉบับ
3. เกณฑ์การตรวจรับให้ตัวอย่างเพียงบางส่วนเพื่อทำความเข้าใจกฎ **ไม่ได้ครอบคลุมทุกกรณี** ผู้ทดสอบต้องวิเคราะห์เองว่าควรทดสอบค่าใด ทั้งค่าขอบเขต กลุ่มค่าที่เทียบเท่า ลำดับขั้นตอน และการผสมเงื่อนไขข้ามฟีเจอร์
4. ข้อกำหนดที่ใช้คำว่า "ต้อง" เป็นข้อบังคับ ข้อความในหัวข้อ "สมมติฐาน" เป็นเพียงบริบท ไม่ใช่ข้อกำหนด

| เอกสาร | เนื้อหา |
|---|---|
| `glossary.md` | อภิธานศัพท์ นิยามราคา การปัดเศษ เวลา สถานะ |
| `PRD-COMMON.md` | มาตรฐานพื้นฐาน: สถานะ HTTP รูปแบบข้อผิดพลาด การตรวจสอบข้อมูล ความปลอดภัย |
| `PRD-CROSS.md` | กฎข้ามฟีเจอร์: ลำดับการคำนวณราคา สต็อก คูปอง ยอดขาย |
| `PRD-AUTH.md` | การลงทะเบียน การเข้าสู่ระบบ การล็อกบัญชี เซสชัน การเปลี่ยนรหัสผ่าน |

| `PRD-CATALOG.md` | การเรียกดู ค้นหา กรอง เรียงสินค้า และการจัดการสินค้า |
| `PRD-CART.md` | ตะกร้าสินค้าและการคำนวณราคา |
| `PRD-COUPON.md` | คูปองและการจัดการคูปอง |
| `PRD-ORDER.md` | การสั่งซื้อ การชำระเงิน สถานะ การยกเลิก การคืนสินค้า |
| `PRD-WISHLIST.md` | รายการโปรด |
| `PRD-REVIEW.md` | รีวิวและคะแนนสินค้า |
| `PRD-INVENTORY.md` | สต็อกและประวัติการเคลื่อนไหว |
| `PRD-REPORT.md` | รายงานยอดขายและการส่งออก CSV |
| `PRD-ADMIN.md` | การจัดการผู้ใช้ |
| `PRD-SCHEDULE.md` | งานตั้งเวลาทุกชั่วโมง |

## 3. ระบบรหัส

| รหัส | รูปแบบ | ตัวอย่าง |
|---|---|---|
| ข้อกำหนด | `REQ-<ฟีเจอร์>-<เลข 3 หลัก>` | `REQ-CART-006` |
| เกณฑ์การตรวจรับ | `AC-<ฟีเจอร์>-<เลข REQ>.<ลำดับ>` | `AC-CART-006.2` |

รหัสฟีเจอร์ ได้แก่ `AUTH`, `PROF`, `CAT`, `CART`, `COUP`, `ORD`, `WISH`, `REV`, `INV`, `RPT`, `ADM`, `SCH`, `COM`, `CROSS`

## 4. โครงสร้างของ PRD แต่ละฉบับ

1. ภาพรวม
2. ขอบเขต (อยู่ในขอบเขต / อยู่นอกขอบเขต)
3. ข้อกำหนด: แต่ละข้อกำหนดมีกฎ และตารางเกณฑ์การตรวจรับในรูป Given / When / Then
4. สมมติฐาน

## 5. เอกสารที่เกี่ยวข้อง

- เอกสารออกแบบ: `docs/design/` (สถาปัตยกรรม โมเดลข้อมูล API สถานะ สิทธิ์ และหน้าจอ)
- คำแนะนำการใช้งาน: `docs/instructions/`
- ตารางสืบย้อน (traceability): `docs/traceability.md`
- แบบฟอร์มสำหรับผู้ทดสอบ: `exercises/`
