# PRD-SCHEDULE: งานตั้งเวลาทุกชั่วโมง

## 1. ภาพรวม

ระบบมีงานที่ทำงานโดยอัตโนมัติทุกต้นชั่วโมง 3 งาน ได้แก่ ยกเลิกคำสั่งซื้อที่ค้างชำระ สร้างรายงานยอดขายของชั่วโมงที่ผ่านมา และบันทึกรายการสินค้าใกล้หมด ผู้ดูแลระบบดูตารางงาน ประวัติการรัน และสั่งรันงานด้วยตนเองได้

## 2. ขอบเขต

**อยู่ในขอบเขต:** ตารางเวลา งานทั้งสาม การรันด้วยตนเอง ประวัติการรัน และหน้าจอ Jobs

**อยู่นอกขอบเขต:** การเพิ่มหรือแก้ไขตารางเวลาของงาน การรันย้อนหลังงานที่พลาด (ระบบไม่รันย้อนหลัง) และการแจ้งเตือนเมื่องานล้มเหลว

## 3. ข้อกำหนด

### REQ-SCH-001: ตารางเวลา

- งานทั้งสามทำงานทุกชั่วโมงที่นาทีที่ 0 ตามเวลา Asia/Bangkok (เช่น 14:00, 15:00) โดยเริ่มทีละงานตามลำดับ `cancel-unpaid-orders`, `hourly-sales-report`, `low-stock-snapshot`
- หากระบบไม่ได้ทำงานในเวลาที่กำหนด ระบบไม่รันย้อนหลังงานของชั่วโมงที่พลาด
- `GET /api/admin/jobs` ตอบ 200 ในรูป `{ "items": [ { "name", "description", "schedule", "last_run", "next_run_at" } ] }` ครบทั้งสามงาน
  - `schedule` เป็นข้อความ `Every hour at minute 0 (Asia/Bangkok)`
  - `last_run` เป็นบันทึกการรันล่าสุด (รูปแบบเดียวกับ `REQ-SCH-006`) หรือ `null` หากยังไม่เคยรัน
  - `next_run_at` คือต้นชั่วโมงถัดไปนับจากเวลาปัจจุบัน (เช่น ถ้าตอนนี้ 14:25 ค่าคือ 15:00 ของวันเดียวกัน)

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-SCH-001.1 | เวลาปัจจุบันคือ 14:25 | `admin1` เรียก `GET /api/admin/jobs` | `next_run_at` ของทุกงานเป็น 15:00 ของวันเดียวกัน (ส่วนต่างเวลา `+07:00`) |

### REQ-SCH-002: งาน cancel-unpaid-orders

- งานนี้ยกเลิกคำสั่งซื้อสถานะ `PENDING_PAYMENT` ที่มีอายุตั้งแต่ **60 นาทีขึ้นไป** นับจากเวลาสร้างถึงเวลาที่งานเริ่มทำงาน (คำสั่งซื้อที่อายุ 60 นาทีพอดีถูกยกเลิก คำสั่งซื้อที่อายุ 59 นาทีไม่ถูกยกเลิก)
- คำสั่งซื้อสถานะอื่นทุกสถานะ (รวม `PAID` ที่มีอายุเกิน 60 นาที) ต้องไม่ถูกแตะต้อง
- คำสั่งซื้อที่ถูกยกเลิกต้องได้ผลเหมือนการยกเลิกปกติตาม `REQ-ORD-005` ได้แก่ สถานะ `CANCELLED` พร้อม `cancelled_at` คืนสต็อก (รายการเคลื่อนไหวเหตุผล `CANCEL` ผู้ดำเนินการ `system`) คืนสิทธิ์คูปอง และ `refund_amount` เป็น 0.00
- สรุปผล (`summary`) ของการรันคือ `{ "cancelled_count": <จำนวน>, "order_ids": [<รหัสเรียงจากน้อยไปมาก>] }`
- การรันซ้ำต้องไม่ส่งผลกับคำสั่งซื้อที่ถูกยกเลิกไปแล้ว (ไม่คืนสต็อกซ้ำ)

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-SCH-002.1 | `customer2` มีคำสั่งซื้อ `PENDING_PAYMENT` อายุ 61 นาที และอีกรายการอายุ 59 นาที | รันงาน `cancel-unpaid-orders` | รายการอายุ 61 นาทีถูกยกเลิก รายการอายุ 59 นาทียังเป็น `PENDING_PAYMENT` |
| AC-SCH-002.2 | `customer2` มีคำสั่งซื้อ `PAID` ที่ชำระเงินมาแล้ว 90 นาที | รันงาน `cancel-unpaid-orders` | คำสั่งซื้อนั้นยังเป็น `PAID` |
| AC-SCH-002.3 | งานเพิ่งยกเลิกคำสั่งซื้อ X | รันงานซ้ำทันที | `cancelled_count` เป็น 0 และสต็อกไม่เปลี่ยนจากหลังรันครั้งแรก |

### REQ-SCH-003: งาน hourly-sales-report

- งานนี้สร้างแถวรายงานของช่วงเวลา `[window_start, window_end)` โดยการรันตามตารางใช้ช่วงของชั่วโมงเต็มที่ผ่านมา (เช่น เมื่อรันเวลา 15:00 ช่วงคือ `[14:00, 15:00)`)
- นับคำสั่งซื้อตาม `REQ-CROSS-006` ที่ `paid_at` อยู่ในช่วง (คำสั่งซื้อที่ชำระเวลา 14:00:00 พอดีนับอยู่ในช่วง `[14:00, 15:00)` และไม่นับในช่วง `[13:00, 14:00)`)
- ค่าในแถว: `order_count`, `gross_sales`, `vat_total`, `shipping_total`, `discount_total` นิยามเหมือนรายงานตาม `REQ-RPT-001`
- ช่วงที่ไม่มีคำสั่งซื้อต้องได้แถวรายงานที่ค่าทุกตัวเป็นศูนย์ ไม่ใช่ไม่มีแถว
- แถวรายงานมีความไม่ซ้ำตามคู่ `window_start` และ `window_end` การรันช่วงเดิมซ้ำต้องเขียนทับแถวเดิม ไม่เพิ่มแถวใหม่
- `summary` ของการรันคือ `{ "window_start", "window_end", "order_count" }`

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-SCH-003.1 | มีคำสั่งซื้อที่ชำระเงินแล้ว 2 รายการภายในช่วง W | `admin1` รันงานด้วยช่วง W | แถวรายงานของ W มี `order_count` เป็น 2 และ `gross_sales` เท่ากับผลรวม `grand_total` ของทั้งสองรายการ |
| AC-SCH-003.2 | รันงานช่วง W ไปแล้ว | รันงานช่วง W อีกครั้ง | รายงานของ W ยังมีเพียง 1 แถว |
| AC-SCH-003.3 | ไม่มีคำสั่งซื้อในช่วง W2 | รันงานช่วง W2 | มีแถวของ W2 ที่ค่าทั้งหมดเป็น 0 (จำนวนเงินเป็น `"0.00"`) |

### REQ-SCH-004: งาน low-stock-snapshot

- งานนี้บันทึกรายการสินค้าที่ `active = true` และสต็อกไม่เกิน 5 เป็น snapshot ใหม่ แทนที่ snapshot เดิม พร้อมเวลา `taken_at`
- รายการเรียงตามที่กำหนดใน `REQ-INV-004`
- `summary` ของการรันคือ `{ "item_count": <จำนวน> }`

### REQ-SCH-005: การรันด้วยตนเอง

`POST /api/admin/jobs/{name}/run` เฉพาะ `admin` ใช้ได้ (บทบาทอื่นได้ 403) ตอบ 200 พร้อมบันทึกการรัน

- `name` ต้องเป็นหนึ่งในสามงาน มิฉะนั้นตอบ 404 `NOT_FOUND`
- สำหรับ `hourly-sales-report` คำขออาจมีเนื้อหา `{ "from": "<เวลา>", "to": "<เวลา>" }` เพื่อกำหนดช่วง `[from, to)` เอง โดย `from` และ `to` อยู่ในรูปแบบเวลาของคูปอง (ระดับนาที ไม่มีวินาที) `to` ต้องหลัง `from` และช่วงต้องไม่เกิน 24 ชั่วโมง มิฉะนั้นตอบ 400 `VALIDATION_ERROR` หากไม่ส่งเนื้อหา ให้ใช้ชั่วโมงเต็มที่ผ่านมา
- เนื้อหาคำขอของงานอื่นถูกละเว้น
- การรันด้วยตนเองบันทึก `trigger` เป็น `MANUAL` และ `triggered_by` เป็นชื่อผู้ใช้ที่สั่งรัน

### REQ-SCH-006: ประวัติการรัน

`GET /api/admin/jobs/{name}/runs` แบ่งหน้าตาม `REQ-COM-011` เรียงจากใหม่ไปเก่า แต่ละรายการมี

| ฟิลด์ | ความหมาย |
|---|---|
| `id` | รหัสการรัน |
| `job` | ชื่องาน |
| `trigger` | `SCHEDULED` หรือ `MANUAL` |
| `triggered_by` | `system` สำหรับการรันตามตาราง หรือชื่อผู้ใช้ |
| `status` | `RUNNING`, `SUCCESS`, `FAILED` |
| `started_at`, `finished_at` | เวลาเริ่มและเวลาจบ (`finished_at` เป็น `null` ขณะ `RUNNING`) |
| `summary` | สรุปผลตามที่กำหนดของแต่ละงาน (`null` เมื่อ `FAILED`) |
| `error_message` | `Job failed.` เมื่อ `FAILED` มิฉะนั้น `null` |

### REQ-SCH-007: ไม่รันซ้อน

- หากงานใดกำลังทำงานอยู่ (`RUNNING`) การสั่งรันด้วยตนเองของงานเดียวกันต้องตอบ 409 `JOB_ALREADY_RUNNING` และไม่เริ่มการรันใหม่ แม้มีคำขอเข้ามาพร้อมกัน ต้องมีการรันเพียงหนึ่งรายการ
- การรันตามตารางที่พบว่างานนั้นกำลังทำงานอยู่ ให้ข้ามไปโดยไม่สร้างบันทึกการรัน

### REQ-SCH-008: ความล้มเหลวของงาน

- แต่ละการรันต้องทำงานภายใต้ธุรกรรมเดียว หากเกิดข้อผิดพลาด ต้องย้อนการเปลี่ยนแปลงทั้งหมดของการรันนั้น และบันทึกสถานะ `FAILED`
- ความล้มเหลวของงานหนึ่งต้องไม่ขัดขวางการทำงานของงานอื่น

### REQ-SCH-009: หน้าจอ Jobs

หน้า `/admin/jobs` แสดงตารางงาน (ชื่อ คำอธิบาย ตารางเวลา การรันล่าสุดพร้อมป้ายสถานะและเวลาในรูป `dd/MM/yyyy HH:mm` เวลาการรันครั้งถัดไป) และปุ่ม Run now ที่ต้องยืนยันก่อน ปิดใช้งานระหว่างส่งคำขอเพื่อป้องกันการกดซ้ำ สำหรับ `hourly-sales-report` ปุ่ม Run now เปิดกล่องข้อความให้ระบุช่วงเวลา (ไม่บังคับ) ได้ละเอียดระดับนาที ผลสรุปของการรันแสดงบนหน้าจอหลังรันเสร็จ และมีลิงก์ View history ไปยังประวัติการรัน
