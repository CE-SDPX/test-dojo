# PRD-COUPON: คูปองส่วนลดและการจัดการคูปอง

## 1. ภาพรวม

ลูกค้าใช้คูปองเพื่อรับส่วนลดเพิ่มเติมจากส่วนลดตามยอด ผู้จัดการและผู้ดูแลระบบสร้างและบริหารคูปอง คูปองแต่ละใบมีช่วงเวลาที่ใช้ได้ ซึ่งกำหนดด้วยวันที่และเวลาระดับนาที

## 2. ขอบเขต

**อยู่ในขอบเขต:** นิยามคูปอง เงื่อนไขการใช้ได้ การคำนวณส่วนลด การใส่และลบคูปองในตะกร้า การนับสิทธิ์ การตรวจสอบซ้ำตอนสั่งซื้อ และการจัดการคูปอง

**อยู่นอกขอบเขต:** คูปองเฉพาะสินค้าหรือหมวดหมู่ คูปองเฉพาะผู้ใช้ การส่งคูปองให้ลูกค้า และการใช้คูปองหลายใบพร้อมกัน

## 3. ข้อกำหนด

### REQ-COUP-001: นิยามคูปอง

| ฟิลด์ | กฎ |
|---|---|
| `code` | 4 ถึง 20 อักขระ ใช้ได้เฉพาะ `A-Z` และ `0-9` จัดเก็บเป็นตัวพิมพ์ใหญ่ ไม่ซ้ำกันโดยไม่แยกตัวพิมพ์ ไม่เปลี่ยนแปลงหลังสร้าง |
| `type` | `PERCENT` (ลดเป็นเปอร์เซ็นต์) หรือ `FIXED` (ลดเป็นจำนวนเงินคงที่) ไม่เปลี่ยนแปลงหลังสร้าง |
| `percent_off` | จำเป็นสำหรับ `PERCENT` เป็นจำนวนเต็ม 1 ถึง 100 สำหรับ `FIXED` ฟิลด์นี้ถูกละเว้น |
| `amount_off` | จำเป็นสำหรับ `FIXED` เป็นจำนวนเงิน 0.01 ถึง 99999.99 สำหรับ `PERCENT` ฟิลด์นี้ถูกละเว้น |
| `max_discount` | ไม่จำเป็น ใช้กับ `PERCENT` เท่านั้น เป็นจำนวนเงิน 0.01 ถึง 99999.99 (ค่า `null` หมายถึงไม่จำกัดเพดาน) |
| `min_spend` | ยอดขั้นต่ำ 0.00 ถึง 99999.99 ค่าเริ่มต้น 0.00 |
| `starts_at` | เวลาเริ่มใช้ได้ ระดับนาที ตามรูปแบบเวลาของคูปอง (ดูด้านล่าง) |
| `expires_at` | เวลาสิ้นสุด ระดับนาที |
| `per_user_limit` | จำนวนครั้งสูงสุดต่อผู้ใช้ จำนวนเต็ม 1 ถึง 99 ค่าเริ่มต้น 1 |
| `total_limit` | จำนวนครั้งสูงสุดรวมทุกผู้ใช้ จำนวนเต็ม 1 ถึง 1000000 หรือ `null` (ไม่จำกัด) ค่าเริ่มต้น `null` |
| `active` | เปิดใช้งานหรือไม่ ค่าเริ่มต้น `true` |

**รูปแบบเวลาของคูปอง:** `YYYY-MM-DDTHH:mm` ตามด้วยส่วนต่างเวลา (`+07:00`, `-05:00` หรือ `Z`) ไม่มีวินาที เช่น `2026-10-10T14:30+07:00` หากคำขอมีวินาทีหรือรูปแบบอื่น ต้องตอบ 400 `VALIDATION_ERROR` ระบบต้องแปลงเวลาตามส่วนต่างเวลาที่ระบุให้ถูกต้อง และส่งออกในรูป `+07:00` เสมอ `starts_at` ต้องไม่หลัง `expires_at` (เท่ากันได้ ซึ่งหมายถึงคูปองที่ใช้ได้เพียง 1 นาที) มิฉะนั้นตอบ 400 `VALIDATION_ERROR` ที่ฟิลด์ `expires_at`

### REQ-COUP-002: เงื่อนไขการใช้ได้

ให้ **t** เป็นเวลาปัจจุบันที่ตัดวินาทีทิ้ง (ละเอียดระดับนาที) คูปองใช้ได้ก็ต่อเมื่อเงื่อนไขทุกข้อต่อไปนี้เป็นจริง และเมื่อไม่เป็นจริง ให้รายงานเหตุผลข้อแรกตามลำดับในตาราง

| ลำดับ | เงื่อนไข | เหตุผล (`reason`) | ข้อความ |
|---|---|---|---|
| 1 | พบคูปองตามรหัส และ `active = true` | `NOT_FOUND` | `This coupon code is not valid.` |
| 2 | t ไม่ก่อน `starts_at` | `NOT_STARTED` | `This coupon is not active yet.` |
| 3 | t ไม่หลัง `expires_at` | `EXPIRED` | `This coupon has expired.` |
| 4 | ยอดหลังส่วนลดตามยอด ≥ `min_spend` | `MIN_SPEND` | `Spend at least ฿{min_spend} to use this coupon.` |
| 5 | จำนวนครั้งที่ผู้ใช้นี้ใช้แล้ว < `per_user_limit` | `USER_LIMIT` | `You have already used this coupon.` |
| 6 | จำนวนครั้งที่ใช้แล้วรวม < `total_limit` (เมื่อกำหนด) | `TOTAL_LIMIT` | `This coupon is no longer available.` |

- คูปองใช้ได้ตั้งแต่ต้นนาที `starts_at` ถึงสิ้นนาที `expires_at` (รวมทั้งสองนาที) ตัวอย่าง: คูปองที่ `expires_at` เป็น 14:30 ยังใช้ได้เมื่อเวลา 14:30:59 และใช้ไม่ได้เมื่อเวลา 14:31:00
- `{min_spend}` ในข้อความแสดงเป็นรูปแบบจำนวนเงินของหน้าจอ เช่น `500.00` ต่อจากสัญลักษณ์ `฿` และตัวคั่นหลักพัน
- การนับ "จำนวนครั้งที่ใช้แล้ว" เป็นไปตาม `REQ-CROSS-005`

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-COUP-002.1 | `FLAT100` มี `min_spend` 500.00 และตะกร้ามีสินค้า Wireless Mouse ×1 (599.00) | ใส่คูปอง `FLAT100` | ใช้ได้ (ยอดหลังส่วนลดตามยอด 599.00 ไม่ต่ำกว่า 500.00) |
| AC-COUP-002.2 | `OLD2025` หมดอายุแล้ว | ใส่คูปอง `OLD2025` | ได้ 409 `COUPON_INVALID` `reason = EXPIRED` |
| AC-COUP-002.3 | `customer2` เคยสั่งซื้อโดยใช้ `SAVE10` สำเร็จแล้ว และไม่ถูกยกเลิก | ใส่คูปอง `SAVE10` | ได้ 409 `COUPON_INVALID` `reason = USER_LIMIT` |
| AC-COUP-002.4 | ผู้จัดการสร้างคูปองที่ `expires_at` เป็นนาทีถัดไป | ลูกค้าใส่คูปองภายในนาทีนั้น และอีกครั้งหลังพ้นนาทีนั้น | ครั้งแรกใช้ได้ ครั้งหลังได้ `reason = EXPIRED` |

### REQ-COUP-003: การคำนวณส่วนลดคูปอง

ให้ A เป็นยอดหลังส่วนลดตามยอด

- `PERCENT`: ส่วนลด = A × `percent_off` ÷ 100 ปัดเศษ half-up เป็น 2 ตำแหน่ง จากนั้นหากมี `max_discount` และส่วนลดเกิน `max_discount` ให้ใช้ `max_discount`
- `FIXED`: ส่วนลด = `amount_off`
- ส่วนลดที่ได้ต้องไม่เกิน A (ยอดสินค้าต้องไม่ติดลบ)

ตัวอย่าง: `SAVE10` (10%, สูงสุด 200.00) กับ A = 1,537.20 → ส่วนลด 153.72, กับ A = 3,600.00 → ส่วนลด 200.00 และ `BIGFLAT` (5,000.00) กับ A = 75.00 → ส่วนลด 75.00

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-COUP-003.1 | ตะกร้ามี Sticky Notes Pack ×3 (75.00) | ใส่คูปอง `BIGFLAT` | ส่วนลดคูปองเป็น 75.00 ยอดสินค้าเป็น 0.00 |

### REQ-COUP-004: การใส่ เปลี่ยน และลบคูปองในตะกร้า

- `PUT /api/cart/coupon` รับ `code` ตอบ 200 พร้อมตะกร้าทั้งใบ หาก `code` ว่างหลังตัดช่องว่างตอบ 400 `VALIDATION_ERROR` หากตะกร้าว่างตอบ 409 `CART_EMPTY` หากไม่ผ่านเงื่อนไขตาม `REQ-COUP-002` ตอบ 409 `COUPON_INVALID` พร้อมฟิลด์ `reason` ในออบเจ็กต์ `error` และข้อความตามตาราง
- ตะกร้าใช้คูปองได้เพียง 1 ใบ การใส่คูปองใบใหม่ที่ใช้ได้จะแทนที่ใบเดิม หากใบใหม่ใช้ไม่ได้ ให้คงใบเดิมไว้
- `DELETE /api/cart/coupon` ลบคูปองออกจากตะกร้า ตอบ 200 พร้อมตะกร้า (ตอบ 200 แม้ไม่มีคูปองอยู่) และยอดต้องกลับเป็นเหมือนไม่เคยใส่คูปอง
- ตะกร้าประเมินเงื่อนไขของคูปองใหม่ทุกครั้งที่เรียกดู ฟิลด์ `coupon` ในการตอบกลับตะกร้าเป็น
  - `null` เมื่อไม่มีคูปอง
  - `{ "code": "SAVE10", "valid": true, "message": null }` เมื่อใช้ได้
  - `{ "code": "SAVE10", "valid": false, "message": "<ข้อความตาม REQ-COUP-002>" }` เมื่อคูปองที่ใส่ไว้ใช้ไม่ได้แล้ว (เช่น หมดอายุหรือยอดต่ำกว่าขั้นต่ำเพราะแก้จำนวนสินค้า) โดย `coupon_discount` เป็น 0.00 และคูปองยังคงอยู่ในตะกร้า

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-COUP-004.1 | ตะกร้าใช้คูปอง `SAVE10` อยู่ | ใส่คูปอง `FLAT100` ที่ใช้ได้ | ตะกร้าใช้ `FLAT100` เพียงใบเดียว |
| AC-COUP-004.2 | ตะกร้าใช้ `FLAT100` (ขั้นต่ำ 500.00) ที่ยอด 599.00 | ลดจำนวนสินค้าจนยอดต่ำกว่า 500.00 | `coupon.valid = false` และ `coupon_discount = 0.00` |
| AC-COUP-004.3 | ตะกร้าใช้ `SAVE10` | ลบคูปอง | `coupon = null` และ `coupon_discount = 0.00` |

### REQ-COUP-005: การจับคู่รหัสคูปอง

รหัสที่ลูกค้าป้อนถูกตัดช่องว่างหน้า-หลังและเปรียบเทียบโดยไม่แยกตัวพิมพ์ใหญ่-เล็ก (`" save10 "` ใช้ได้เท่ากับ `SAVE10`)

### REQ-COUP-006: การนับสิทธิ์และการใช้งานพร้อมกัน

- การนับสิทธิ์เป็นไปตาม `REQ-CROSS-005`
- ระบบต้องไม่ให้จำนวนคำสั่งซื้อที่ใช้คูปองเกิน `total_limit` หรือ `per_user_limit` ไม่ว่าคำขอสร้างคำสั่งซื้อจะเข้ามาพร้อมกันกี่รายการ รายการที่เกินสิทธิ์ต้องได้ 409 `COUPON_INVALID`

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-COUP-006.1 | คูปอง `LASTONE` มี `total_limit` 1 และยังไม่มีผู้ใช้ ลูกค้า 2 คนมีคูปองนี้ในตะกร้า | ทั้งสองส่งคำขอสร้างคำสั่งซื้อพร้อมกัน | สำเร็จเพียงคนเดียว อีกคนได้ 409 `COUPON_INVALID` |
| AC-COUP-006.2 | ลูกค้าสั่งซื้อด้วย `SAVE10` สำเร็จ แล้วยกเลิกคำสั่งซื้อนั้น | ใส่คูปอง `SAVE10` ในตะกร้าใหม่ | ใช้ได้อีกครั้ง |

### REQ-COUP-007: การตรวจสอบซ้ำเมื่อสร้างคำสั่งซื้อ

เมื่อสร้างคำสั่งซื้อ ระบบต้องประเมินเงื่อนไขของคูปองในตะกร้าอีกครั้ง ณ เวลานั้น หากไม่ผ่านต้องตอบ 409 `COUPON_INVALID` และไม่สร้างคำสั่งซื้อ

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-COUP-007.1 | ตะกร้าใช้คูปองที่หมดอายุไปแล้วหลังจากใส่เข้าตะกร้า | ลูกค้าสั่งซื้อ | ได้ 409 `COUPON_INVALID` `reason = EXPIRED` และไม่มีคำสั่งซื้อเกิดขึ้น |

### REQ-COUP-008: การจัดการคูปอง (manager และ admin)

เฉพาะ `manager` และ `admin` ใช้ได้ บทบาทอื่นได้ 403

- `GET /api/manage/coupons`: รายการคูปองทั้งหมด ค้นหาด้วย `q` (ข้อความเป็นส่วนหนึ่งของ `code` ไม่แยกตัวพิมพ์) เรียงตาม `code` จากน้อยไปมาก แบ่งหน้าตาม `REQ-COM-011` แต่ละรายการมีฟิลด์ของ `REQ-COUP-001` พร้อม `id`, `status`, `usage_count`, `created_at`
- `POST /api/manage/coupons`: สร้างคูปอง ตอบ 201 หากรหัสซ้ำ (ไม่แยกตัวพิมพ์) ตอบ 409 `COUPON_CODE_TAKEN`
- `PUT /api/manage/coupons/{id}`: แก้ไข `percent_off`, `amount_off`, `max_discount`, `min_spend`, `starts_at`, `expires_at`, `per_user_limit`, `total_limit` ตอบ 200 ส่วน `code` และ `type` ถูกละเว้น การแก้ไขมีผลกับการประเมินครั้งถัดไปเท่านั้น และไม่เปลี่ยนคำสั่งซื้อที่สร้างแล้ว
- `PATCH /api/manage/coupons/{id}/active` รับ `{ "active": true|false }` ตอบ 200
- `usage_count` คือจำนวนคำสั่งซื้อที่ใช้คูปองนั้นและมีสถานะไม่ใช่ `CANCELLED`

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-COUP-008.1 | `manager1` ล็อกอินแล้ว | สร้างคูปองที่ `expires_at` ก่อน `starts_at` | ได้ 400 `VALIDATION_ERROR` ที่ฟิลด์ `expires_at` |
| AC-COUP-008.2 | `customer1` ล็อกอินแล้ว | เรียก `POST /api/manage/coupons` | ได้ 403 `FORBIDDEN` |
| AC-COUP-008.3 | `manager1` ล็อกอินแล้ว | สร้างคูปองที่ `expires_at` มีวินาที เช่น `2026-10-10T14:30:45+07:00` | ได้ 400 `VALIDATION_ERROR` |

### REQ-COUP-009: สถานะของคูปอง

สถานะคำนวณจากข้อมูลและเวลาปัจจุบัน t (ตัดวินาที) ดังนี้ ตรวจตามลำดับ

| ลำดับ | เงื่อนไข | สถานะ |
|---|---|---|
| 1 | `active = false` | `DISABLED` |
| 2 | t ก่อน `starts_at` | `SCHEDULED` |
| 3 | t หลัง `expires_at` | `EXPIRED` |
| 4 | นอกเหนือจากนี้ | `ACTIVE` |

### REQ-COUP-010: การแสดงเวลาและแบบฟอร์มคูปองบนหน้าจอ

- ช่องกำหนด `starts_at` และ `expires_at` เลือกวันและเวลาได้ละเอียดระดับนาที พร้อมป้ายระบุเขตเวลา `Asia/Bangkok (UTC+07:00)` และเวลาที่ผู้ใช้เลือกต้องตรงกับที่ API เก็บและแสดงกลับ
- รายการคูปองแสดงเวลาในรูปแบบ `dd/MM/yyyy HH:mm` และแสดงสถานะเป็นป้าย `Active`, `Scheduled`, `Expired`, `Disabled`
- ข้อความตามที่กำหนดใน `docs/design/ui/copy-deck.md`
