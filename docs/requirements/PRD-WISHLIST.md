# PRD-WISHLIST: รายการโปรด

## 1. ภาพรวม

ลูกค้าบันทึกสินค้าที่สนใจไว้ในรายการโปรดเพื่อกลับมาดูภายหลัง

## 2. ขอบเขต

**อยู่ในขอบเขต:** การเพิ่ม ลบ และดูรายการโปรดของลูกค้า

**อยู่นอกขอบเขต:** การแชร์รายการโปรด และการแจ้งเตือนเมื่อสินค้าลดราคา

## 3. ข้อกำหนด

เฉพาะบทบาท `customer` ใช้ endpoint ของรายการโปรดได้ บทบาทอื่นได้ 403 `FORBIDDEN`

### REQ-WISH-001: การเพิ่มสินค้าในรายการโปรด

`PUT /api/wishlist/{product_id}` ไม่มีเนื้อหาคำขอ ตอบ 201 พร้อม `{ "product_id": 1, "added_at": "<เวลา>" }`

- สินค้าต้องมีอยู่และ `active = true` มิฉะนั้นตอบ 404 `NOT_FOUND`
- หากสินค้านั้นอยู่ในรายการโปรดแล้ว ตอบ 409 `ALREADY_IN_WISHLIST` และต้องไม่เกิดรายการซ้ำ
- รายการโปรดมีได้ไม่เกิน 50 รายการ การเพิ่มรายการที่ 51 ตอบ 409 `WISHLIST_LIMIT`
- ลำดับการตรวจ: 404 → `ALREADY_IN_WISHLIST` → `WISHLIST_LIMIT`

**เกณฑ์การตรวจรับ**

| ID | Given | When | Then |
|---|---|---|---|
| AC-WISH-001.1 | `customer1` ยังไม่มีรายการโปรด | เพิ่ม Scented Candle | ได้ 201 และรายการโปรดมี 1 รายการ |
| AC-WISH-001.2 | เพิ่ม Scented Candle ไปแล้ว | เพิ่ม Scented Candle ซ้ำ | ได้ 409 `ALREADY_IN_WISHLIST` และรายการโปรดยังมี 1 รายการ |

### REQ-WISH-002: การลบสินค้าออกจากรายการโปรด

`DELETE /api/wishlist/{product_id}` ตอบ 204 หากสินค้านั้นไม่อยู่ในรายการโปรดของผู้เรียก ตอบ 404 `NOT_FOUND`

### REQ-WISH-003: การดูรายการโปรด

- `GET /api/wishlist` ตอบ 200 ในรูป `{ "items": [...] }` ไม่แบ่งหน้า
- แต่ละรายการมี `product_id`, `sku`, `name`, `price`, `stock_status`, `added_at`
- เรียงจากรายการที่เพิ่มล่าสุดไปเก่าสุด (ถ้าเวลาเท่ากันเรียง `product_id` จากมากไปน้อย)
- รายการโปรดเป็นของผู้ใช้แต่ละคน ผู้ใช้เห็นเฉพาะรายการของตน
- สินค้าที่ถูกปิดการใช้งานต้องไม่อยู่ในรายการ (ตาม `REQ-CAT-009`)

### REQ-WISH-004: หน้ารายการโปรดและปุ่มบนหน้าสินค้า

- หน้า `/wishlist` แสดงสินค้าแต่ละรายการพร้อมปุ่ม Remove และ Add to cart (ปิดใช้งานเมื่อสินค้าหมดสต็อก) เมื่อไม่มีรายการแสดง `Your wishlist is empty.`
- หน้ารายละเอียดสินค้ามีปุ่มรายการโปรด ที่เปลี่ยนข้อความระหว่าง `Add to wishlist` และ `Remove from wishlist` ตามสถานะจริง
