# แนวทางการออกแบบหน้าจอ (UI Guidelines)

เอกสารนี้กำหนดกฎการจัดวาง การแสดงผล การเข้าถึง (accessibility) และพฤติกรรมของหน้าจอที่ใช้ร่วมกันทุกหน้า ข้อความที่แสดงกำหนดใน `copy-deck.md` และโครงของแต่ละหน้ากำหนดใน `wireframes.md` พฤติกรรมของหน้าจอที่ขัดกับเอกสารเหล่านี้ถือว่าไม่เป็นไปตามข้อกำหนด

## 1. การรองรับขนาดหน้าจอ

| ช่วงความกว้าง | ชื่อ | พฤติกรรม |
|---|---|---|
| 360 ถึง 479 px | มือถือ | เนื้อหาคอลัมน์เดียว เมนูยุบเป็นปุ่ม `Menu` |
| 480 ถึง 767 px | มือถือขนาดใหญ่ | ตารางการ์ดสินค้า 2 คอลัมน์ เมนูยุบเป็นปุ่ม `Menu` |
| 768 ถึง 1279 px | แท็บเล็ต | การ์ดสินค้า 3 คอลัมน์ เมนูแสดงเต็ม |
| 1280 px ขึ้นไป | เดสก์ท็อป | การ์ดสินค้า 4 คอลัมน์ เมนูแสดงเต็ม |

- ระบบรองรับความกว้างต่ำสุด 360 px และรองรับการขยายหน้าเว็บของเบราว์เซอร์ถึง 200% โดยยังใช้งานได้
- ความกว้างของเนื้อหาสูงสุด 1200 px จัดกึ่งกลางหน้า
- หน้าต้องไม่มีแถบเลื่อนแนวนอนระดับหน้า (page-level horizontal scroll) ที่ทุกความกว้างตั้งแต่ 360 px ขึ้นไป ตารางที่กว้างกว่าหน้าจออนุญาตให้เลื่อนแนวนอนภายในกรอบของตารางเองเท่านั้น

## 2. การจัดวางและระยะห่าง

| เรื่อง | กฎ |
|---|---|
| ระยะขอบซ้าย-ขวาของหน้า | 16 px เมื่อกว้างน้อยกว่า 768 px และ 24 px เมื่อกว้างตั้งแต่ 768 px |
| ระยะห่างระหว่างองค์ประกอบ | เป็นพหุคูณของ 8 px |
| ส่วนหัว (header) | สูง 56 px ตรึงอยู่ด้านบน ไม่บังเนื้อหา |
| ส่วนท้าย (footer) | อยู่ท้ายหน้าเสมอ (ถ้าเนื้อหาสั้นให้ชิดล่างของหน้าต่าง) |
| ตัวอักษรพื้นฐาน | 16 px ความสูงบรรทัด 1.5 |
| ขนาดหัวข้อ | `h1` 28 px, `h2` 22 px, `h3` 18 px |
| การจัดตำแหน่งข้อความ | จัดชิดซ้ายเป็นหลัก คอลัมน์จำนวนเงินและจำนวนในตารางจัดชิดขวา |
| ข้อความยาว | ต้องตัดบรรทัดภายในกรอบของตัวเอง ห้ามล้นกรอบ ห้ามทับองค์ประกอบอื่น |
| ชื่อสินค้าบนการ์ด | แสดงสูงสุด 2 บรรทัด ส่วนที่เกินแสดงเป็นจุดไข่ปลา (`…`) และแสดงชื่อเต็มเมื่อชี้เมาส์ (`title`) |
| รูปภาพสินค้า | สัดส่วน 1:1 คงอัตราส่วนเดิม ไม่ยืดหรือบิดเบี้ยว |
| ปุ่มและช่องกรอก | ในแถวเดียวกันต้องจัดแนวกึ่งกลางแนวตั้งและความสูงเท่ากัน |

## 3. สี การมองเห็น และการเข้าถึง

1. อัตราส่วนความต่างสี (contrast) ของข้อความต่อพื้นหลังต้องไม่ต่ำกว่า 4.5:1 สำหรับข้อความปกติ และ 3:1 สำหรับข้อความขนาดใหญ่ (ตั้งแต่ 24 px หรือ 19 px ตัวหนา)
2. ข้อมูลสำคัญ (เช่น ข้อผิดพลาด สถานะ) ต้องไม่สื่อด้วยสีเพียงอย่างเดียว ต้องมีข้อความหรือไอคอนกำกับ
3. องค์ประกอบที่โต้ตอบได้ทุกตัวต้องมีเส้นแสดงโฟกัส (focus indicator) ที่มองเห็นชัด หนาไม่น้อยกว่า 2 px
4. ลำดับการกดแท็บ (Tab) ต้องเป็นไปตามลำดับการมองเห็น (ซ้ายไปขวา บนลงล่าง) และไม่ข้ามองค์ประกอบ
5. ช่องกรอกทุกช่องต้องมีป้ายกำกับ (`label`) ที่มองเห็นและผูกกับช่อง (ไม่ใช้ placeholder แทนป้ายกำกับ) ยกเว้นช่องค้นหาที่ส่วนหัวซึ่งใช้ป้ายกำกับที่อ่านด้วยโปรแกรมอ่านหน้าจอได้
6. ภาพทุกภาพมีข้อความทดแทน (`alt`) ในรูป `Photo of {ชื่อสินค้า}` ส่วนภาพตกแต่งใช้ `alt=""`
7. ปุ่มที่เป็นไอคอนต้องมีชื่อที่อ่านด้วยโปรแกรมอ่านหน้าจอได้
8. องค์ประกอบ `html` กำหนด `lang="en"`
9. ตารางใช้ `th` พร้อม `scope` ในส่วนหัวคอลัมน์
10. พื้นที่กดของปุ่มและลิงก์ต้องกว้างและสูงไม่น้อยกว่า 44 px เมื่อหน้าจอกว้างน้อยกว่า 768 px และไม่น้อยกว่า 32 px ในช่วงอื่น

## 4. ฟอร์ม

- ป้ายกำกับอยู่เหนือช่องกรอก
- ช่องที่จำเป็นทำเครื่องหมาย `*` ต่อท้ายป้ายกำกับ และมีข้อความ `* Required` ที่ท้ายฟอร์ม
- ข้อผิดพลาดของแต่ละฟิลด์แสดงใต้ช่องนั้นด้วยตัวอักษรสีแดงและเชื่อมกับช่องด้วย `aria-describedby` เมื่อมีหลายข้อผิดพลาด ให้แสดงสรุปที่ด้านบนของฟอร์มด้วย และย้ายโฟกัสไปยังช่องแรกที่ผิด
- ช่องกรอกรหัสผ่านใช้ชนิด `password`
- ปุ่มส่งฟอร์มต้องกดได้ด้วยปุ่ม Enter เมื่อโฟกัสอยู่ในช่องกรอก

## 5. พฤติกรรมของหน้าจอ

| เรื่อง | กฎ |
|---|---|
| การกดซ้ำ | ปุ่มที่ส่งคำขอไปยัง API ต้องถูกปิดใช้งานทันทีที่กด และแสดงสถานะกำลังทำงาน (เช่น `Placing order…`) จนกว่าจะได้ผลตอบกลับ การกดซ้ำเร็ว ๆ ต้องส่งคำขอเพียงครั้งเดียว |
| ข้อความสำเร็จ | แสดงเป็นแถบแจ้ง (toast) หายเองหลัง 5 วินาที และปิดได้ด้วยตนเอง |
| ข้อความผิดพลาด | แสดงจนกว่าผู้ใช้ปิด หรือจนกว่าจะดำเนินการใหม่ |
| หน้าต่างยืนยัน (dialog) | ใช้ `role="dialog"` และ `aria-modal="true"` โฟกัสถูกกักอยู่ในหน้าต่าง ปิดได้ด้วย `Esc` เมื่อปิดแล้วโฟกัสกลับไปที่ปุ่มที่เปิด โฟกัสเริ่มต้นอยู่ที่ปุ่มที่ปลอดภัย (`Cancel` หรือ `Keep order`) |
| ผลรวมบนตะกร้า | อัปเดตทันทีหลังทุกการเปลี่ยนแปลงโดยไม่โหลดหน้าใหม่ |
| ระหว่างโหลดข้อมูล | แสดง `Loading…` ในพื้นที่ของเนื้อหา |
| ไม่มีข้อมูล | แสดงข้อความสถานะว่างตาม `copy-deck.md` |
| ตัวกรองและการแบ่งหน้า | สถานะของ `q`, ตัวกรอง และการเรียง ต้องอยู่ใน URL (query string) และคงอยู่เมื่อเปลี่ยนหน้า รีเฟรช หรือกดย้อนกลับ |
| โทเคนหมดอายุ | เมื่อ API ตอบ 401 ระหว่างใช้งาน ให้ล้างโทเคน แล้วนำไปหน้า `/login` พร้อมข้อความ `Your session has expired. Please sign in again.` |
| ออกจากระบบ | ล้างโทเคนที่เก็บไว้ นำไปหน้า `/login` และเมื่อกดย้อนกลับของเบราว์เซอร์ ต้องไม่เห็นเนื้อหาของหน้าส่วนตัว (หน้าต้องตรวจโทเคนใหม่ทุกครั้งที่แสดง รวมถึงจากแคชย้อนกลับ) |
| เมนู | แสดงเฉพาะรายการที่บทบาทเข้าถึงได้ตาม `rbac-matrix.md` รายการของหน้าปัจจุบันแสดงสถานะ "ใช้งานอยู่" (`aria-current="page"`) |
| ลิงก์ลึก | ผู้ที่เปิด URL ของหน้าที่มีสิทธิ์โดยตรงต้องเห็นหน้านั้นหลังตรวจโทเคนแล้ว |

## 6. ตาราง

- หัวตารางคงที่ตามที่ระบุใน `copy-deck.md`
- คอลัมน์ข้อความจัดชิดซ้าย คอลัมน์ตัวเลขและจำนวนเงินจัดชิดขวา และหัวคอลัมน์จัดตามคอลัมน์ของข้อมูล
- ตารางที่แบ่งหน้าแสดงตัวควบคุมการแบ่งหน้าด้านล่าง
- ตารางที่ไม่มีข้อมูลแสดงข้อความสถานะว่างแทนตารางเปล่า

## 7. การแสดงจำนวนเงินและเวลา

เป็นไปตาม `docs/requirements/glossary.md` หัวข้อ 4 และ 5 และตามข้อตกลงใน `copy-deck.md` หัวข้อ 1
