## 2. กรณีทดสอบ

| รหัส | อ้างอิง | ชื่อกรณีทดสอบ | เงื่อนไขก่อนทดสอบ | ขั้นตอน | ข้อมูลทดสอบ | ผลที่คาดหวัง | ผลจริง | ผล | หลักฐาน |
|---|---|---|---|---|---|---|---|---|---|
| TC-001 | `REQ-XXX-000` / `AC-XXX-000.1` | | reset ข้อมูลแล้ว; ล็อกอินด้วย `...` | 1. ... <br> 2. ... | | | | ผ่าน / ไม่ผ่าน | ภาพ / ไฟล์ |

คำอธิบายคอลัมน์

| คอลัมน์ | คำอธิบาย |
|---|---|
| รหัส | รหัสกรณีทดสอบที่ไม่ซ้ำ เช่น `TC-001` |
| อ้างอิง | รหัสข้อกำหนด (REQ) หรือเกณฑ์การตรวจรับ (AC) หรือเอกสารออกแบบที่เกี่ยวข้อง |
| ชื่อกรณีทดสอบ | สั้น บอกสิ่งที่ตรวจ |
| เงื่อนไขก่อนทดสอบ | สถานะข้อมูลที่ต้องมี เช่น ต้อง reset ก่อน บัญชีที่ใช้ ข้อมูลที่ต้องเตรียม |
| ขั้นตอน | ทีละขั้น ทำซ้ำได้โดยผู้อื่น |
| ข้อมูลทดสอบ | ค่าที่ป้อนตรง ๆ |
| ผลที่คาดหวัง | ผลตามเอกสาร ไม่ใช่ผลที่คาดเดา |
| ผลจริง | สิ่งที่เกิดขึ้นจริง รวมรหัสสถานะ ข้อความ ตัวเลข |
| ผล | ผ่าน หรือ ไม่ผ่าน |
| หลักฐาน | ภาพหน้าจอ หรือคำขอและคำตอบของ API |

## 3. เกณฑ์ความชัดเจนของกรณีทดสอบ

กรณีทดสอบที่ดีต้อง

1. สมเหตุสมผล: ตรวจสิ่งที่เอกสารกำหนดไว้จริง
2. ไม่ซ้ำกับกรณีอื่น (ตรวจความเสี่ยงเดียวกันด้วยข้อมูลเทียบเท่า)
3. ชัดเจน: ผู้อื่นอ่านแล้วทำตามได้โดยไม่ต้องเดา
4. ทำซ้ำได้: เริ่มจากข้อมูลเริ่มต้นแล้วได้ผลเดิมทุกครั้ง
5. ตรวจสอบผลได้: ผลที่คาดหวังระบุเป็นค่าหรือข้อความที่เฉพาะเจาะจง
6. ระบุข้อกำหนดที่เกี่ยวข้อง
